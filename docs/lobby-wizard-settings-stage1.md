# LobbyWizard: настройки, этап 1

## Аудит и выбранный маршрут

Существующий выбор системных колод не был удалён: он находится в `DeckScreen`, шаблоне `screen/deck_host.tpl` и обработчике `PrepareProcessor::selectDeck()`. В LobbyWizard вместо него выводилось пояснение об отдельном выборе. `RoomSetup` принимал настройки режимов, но не передавал четыре поля выбора колод в JSON комнаты. Поэтому одного восстановления HTML было недостаточно.

Важная особенность фактического маршрута: `chooseMode(system)` сразу устанавливает `status=deck`. Повторный `confirm_settings` здесь не нужен. Создание комнаты с сохранённым выбором теперь проходит `choose_mode → select_deck → view`. Используется существующий Engine и неизменённый PrepareProcessor; вторая реализация выбора отсутствует. `selectDeck()` по-прежнему проверяет хоста, стадию, отсутствие уже выбранной колоды, способы выбора, принадлежность ID доступным системным колодам и наличие составов. Он назначает обе колоды, создаёт экземпляры карт, очищает подтверждения и переводит игру в View. Подтверждения View и последующий бросок кубиков остаются обязательными.

Обогащение команды серверными ID и полными составами перенесено из `index.php` в `DeckView::selectionPayload()` без изменения полей карт. Оба пути используют этот метод. Случайный выбор разрешается при создании партии. При создании комнаты выполняется предварительная проверка прежним обработчиком на неперсистентном состоянии; полученный там случайный результат не сохраняется. При принятии заявки доступность проверяется заново. Ошибка откатывает существующую транзакцию создания партии. Старые комнаты без `system_decks` сохраняют отдельный DeckScreen.

## UI и сохранение

- Лишние названия режимов убраны только из встроенного содержимого третьего шага. Главный заголовок и пояснение LuckTest сохранены.
- В Grid и Solomon «Бустеры» — второй раздел после основных настроек. В Sealed, по отдельно согласованному исключению, остаются только «Бустеры» без пустого первого раздела.
- Число бустеров, состав и вероятность редкости перенесены без изменения контролов или обработчиков. Состав свёрнут по умолчанию. Используется существующий `details.panel-card-description`; скрытие не отключает поля и не сбрасывает значения.
- Селектор системных колод рендерится самим DeckScreen с прежним шаблоном. Четыре поля сохраняются в `lobby_rooms.setup_json.system_decks`. Схема БД и формат колод не изменены.

## Проверки и доказательства

Изолированный MariaDB/HTTP-стенд; PHP 8.1, Chromium через Yandex Browser. Рабочая БД и production-конфигурации не использовались. Для экономии диска повторная проверка может использовать остановленный datadir этого теста через `WIZARD_SETTINGS_REUSE_LAB`; путь ограничен каталогом `tmp` репозитория. Каждый запуск создаёт отдельную БД и временный web-workspace.

Проверены ручной, случайный и смешанный выбор; сохранение четырёх полей и повторное чтение комнаты; экземпляры обеих колод; отсутствие автоматического подтверждения View; переход в Roll после двух подтверждений; повтор принятия; недопустимые параметры; снятая с публикации колода и откат; старый ручной DeckScreen; запуск всех остальных режимов; сохранение изменённого состава бустера и его применение в созданной партии.

HTTP/БД: 37 проверок пройдены.

Браузер: 31 существующая проверка мастера (включая 360/390 px) и 93 проверки настройки третьего шага во всех пяти режимах при четырёх значениях темы. Ошибок JavaScript нет. Мастер сохраняет своё существующее тёмное оформление; четыре темы относятся к InfoPanel, новые темы для мастера не добавлялись.

PHP lint всех шести изменённых PHP-файлов, синтаксис JavaScript и `test_settings_flow.php` пройдены; `git diff --check` пройден.

Фактические результаты: `docs/evidence/wizard-settings/http-checks.json`, `settings-browser-checks.json`, `wizard/browser-checks.json`.

Скриншоты 1600×900: `docs/evidence/wizard-settings/step3-{draft,solomon,sealed,system}-{grimoire,stone,parchment,leather}.png`.

## Ограничения

- Мастер раньше не поддерживал открытие существующей комнаты для редактирования. Это не добавлялось. Проверено повторное чтение сохранённых настроек комнаты и их применение в партии; повторный вход в новый мастер открывает новую форму с прежними значениями по умолчанию.
- Каталог в изолированной БД тестовый. Скриншоты системного режима показывают тестовую колоду без обложки; реальный production-каталог не проверялся.
- Общая незавершённая HTTP-регрессия боевого таймера из предыдущих этапов остаётся отдельной обязательной проверкой, здесь не объявляется пройденной.
- Engine, PrepareProcessor, генерация бустеров, правила режимов и схема БД не изменены. Commit, push, deploy и миграции рабочей БД не выполнялись.
