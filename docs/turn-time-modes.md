# Три режима времени хода

Реализованы `none`, `fixed`, `adaptive`. Commit, push, deploy и миграции не выполнялись.

## Аудит и реализация

Использован существующий TurnTimer, без второго таймера и изменения Engine, TurnProcessor, pending или протокола паузы. Параметры проходят LobbyWizard → RoomSetup → setup_json комнаты → GameSettings партии. Схема БД не изменяется.

Новые комнаты по умолчанию: fixed, 180 секунд. Fixed: 60–600, шаг 15. Adaptive: 10–120 секунд на существо, шаг 10, по умолчанию 30. Значения сохраняются при переключении режима. UI использует существующий stepper, формат m:ss и отключение кнопок на границах. Настройка отображается в сводке мастера, комнате и списке комнат.

В GameSettings добавлены turn_time_mode, turn_fixed_seconds, turn_creature_seconds. Отсутствующий mode сохраняет историческую интерпретацию turn_seconds: 0 — без таймера, 180 — прежний лимит. Для новых записей turn_seconds остаётся совместимым зеркалом: 0 для none, выбранное значение для fixed, 180 для adaptive; реальный адаптивный лимит вычисляется исключительно новым режимом. Смешанные противоречивые параметры отклоняются сервером.

## Начало логического хода и однократность

Существующие точки жизненного цикла не перенесены:

- `TurnProcessor::startBattle()` (строка 69): первый период после подготовки поля и определения активного игрока, до эффектов начала хода.
- `TurnProcessor::afterEndPhase()` (строка 168): следующий период после завершения всей фазы окончания предыдущего хода, до эффектов начала следующего.
- `TurnProcessor::afterStartPhase()` (строка 470): завершение стартовых процедур и запуск отсчёта; существующий вызов prepare при отсутствии метаданных остаётся восстановительным путём.

Адаптивный бюджет определяется при prepare: собственные живые creature/fly на FIELD/FLYING, без dying и карт с нулевым HP. Бюджет сохраняется в limit_seconds периода. Гибель и появление существ посреди хода его не меняют. Стартовые обязательные ожидания завершаются до запуска отсчёта, как прежде.

В `TurnTimer::prepare()` проверка существующего владельца периода выполняется до подсчёта существ. Повторный lifecycle-вызов с тем же владельцем немедленно возвращается; загрузка и snapshot вообще не создают период. Сохранённые period_id, limit_seconds и remaining_seconds восстанавливаются из GameState. Повтор команды защищён существующим журналом и контролем версии. HTTP-тест потери ответа и повторной отправки подтверждает отсутствие повторного продвижения периода и сброса времени.

Ноль существ обрабатывает существующее штатное поражение. Новая логика поражения или нулевой таймер не добавлялись.

## Проверки

- 68 проверок режимов на реальном ядре с состоянием в памяти.
- 107 изолированных HTTP/БД-проверок (95 основных и 12 граничных): сохранение, все пять режимов игры, делегирование, исторические партии, границы, реальные snapshots, потеря ответа, повтор команды, пауза, pending, однократное истечение и переход хода.
- 97 браузерных проверок (20 времени, 31 мастера, 46 делегирования), включая 360/390 px и реальный боевой таймер на 1200 секунд.
- Расширенная регрессия continuation: исторические 0/180, fixed 225 и adaptive 30; вложенные pending, переходы и порядок Recorder.
- Пройдены test_turn_timeout.php, test_wizard_timer.php (61), test_wizard_informational_wait.php, test_lucktest.php (186), snapshot/UI-часть test_turn_timer_sync.php.
- PHP lint, синтаксис изменённого JavaScript и git diff --check пройдены.

Проверены неизменность бюджета при гибели и появлении существ, новый расчёт на следующем собственном ходу, обычное поражение при нуле существ, пауза и ручное/автоматическое продолжение существующих ожиданий.

## Ограничения

Существующий test_turn_timer_client.js падает на `Same-second authoritative pause is accepted` (01:28 вместо 01:38). То же падение воспроизведено на чистом исходном HEAD 8d9ac44 с неизменёнными клиентскими файлами. В рамках этой задачи оно не исправлялось.

Старая специальная HTTP-регрессия таймера с отдельной конфигурацией berserk_turn_timer_t2_test не запускалась; HTTP-часть test_turn_timer_sync.php пропущена из-за отсутствия TURN_TIMER_TEST_URL. Новые изолированные HTTP/БД-проверки не объявляются заменой всей этой отложенной регрессии. Production не проверялся. Изолированные испытания используют тестовый каталог и подготовленные состояния реального ядра.
