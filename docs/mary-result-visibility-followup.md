# Мэри: результат инстанта за осмотренной картой

В присланном снимке партии 549, version 93, использована `pirate_valor`
(«Пиратская удаль», 1 рана). «Чёрная метка» не отмечена использованной.
Мастер топора — экземпляр 37, `s1_46`, 10/10 HP. Уже разрешённый стек и его
цель в снимке отсутствуют. В доступной локальной БД партии 549 и её истории
нет: установить фактическую цель завершённого действия по этим данным нельзя.

На копии снимка восстановлена доступность Мэри и явно выбрана цель 37.
Штатные declaration → target → pass дают HP **10 → 9** и информационный
результат с `target_id=37`. Копия запускалась в памяти, рабочая БД не менялась.

Воспроизведён отдельный UI-баг: выбор/осмотр карты сохраняется через переход
turn-стека к результату, поскольку оба состояния используют один combat key.
Клиент скрывал информационную область за картой, несмотря на обязательный ACK.

InfoPanel теперь передаёт владельцу текущего ACK идентификатор результата.
При появлении нового результата UI выводит его вперёд, игнорируя старый inspect.
Добровольный осмотр после появления результата сохраняется между одинаковыми
snapshot; закрытие карты возвращает результат. После F5 результат также виден.
Код нанесения ран, владение ACK и серверные продолжения не менялись.

Проверки:

- `test_turn_instant_result_visibility.php`: 13, реальные `prop` Мэри,
  native turn-стек, точная цель и изменение HP, сохранение, устаревший ACK,
  продолжение без повторного урона.
- `test_turn_instant_result_browser.cjs`: 19, Edge 1600/800. Воспроизведён
  прежний контракт без идентификатора результата; проверены новый переход,
  видимость цели/HP/«Продолжить», добровольный осмотр, snapshot и F5.
  Использованы серверные HTML-fixtures; сетевые запросы обслужены локально.
- Прошли реальные turn-карты (28), turn-стек, информационные ожидания/ACK,
  InstantControl UI (57) и combat UI.

Изменены InfoPanel, `battle-ui.js`, версия JS в шаблоне боя и две новые проверки.
