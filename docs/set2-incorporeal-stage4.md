# Set 2 / Stage 4 — бестелесность

## Данные и принятый момент изгнания

Свойство: `prop.incorporeal = true`; тип карты остаётся `creature` (либо существующий тип существа). Класс «Дух» свойства не даёт. Для `s2_116` пользователь добавляет свойство в существующий JSON `prop`, сохраняя остальные поля. Каталог и рабочая БД этим этапом не изменены.

Источник: [правило 89](https://proberserk.ru/rule/89). **По последнему явному уточнению пользователя** изгнание за занятую клетку выполняется сразу после обычного движения, оставившего ноль единиц движения. Это намеренное отличие от исходного текста задания о ближайшем объявлении другого действия. На пустой клетке нулевое движение не вызывает изгнание.

## Аудит и точки интеграции

- `CardInstance::effectiveProp()` — свойства с учётом подавления; `CardStats::isIncorporeal()` — общий предикат, только для существ. Новый тип `spirit` не вводится.
- `BattleHelper::getMoveCells()` — разрешённые клетки; `Movement/MovementResolver::move()` — серверная проверка, стандартный расход движения и эффекты перемещения. Только обычный `move` разрешает занятую клетку. `jump` сохраняет запрет. Маркеры, геометрия, обездвиживание и лимиты продолжают проверяться.
- `CardStats::sharesCell()` — другая самостоятельная карта в той же полевой клетке. Собственный прикреплённый симбиот не создаёт обязанность освободить клетку. Связи хозяина независимым соседям не назначаются.
- `Engine::doApply()` — после pending/choice/single-roll routing проверяет обязанность освободить клетку перед объявлениями основных действий. Пока существует законное обычное движение, нужно двигать соответствующего бестелесного; завершить ход вместо этого нельзя. При отсутствии возможности и положительном движении изгнание не назначается. Для сохранённого состояния с нулём движения и занятой клеткой изгнание выполняется перед следующим основным действием, включая `end_turn`. Внутри strike, turn phase и instant-resolution эта проверка не выполняется.
- `DamageResolver::resolveDeath()` — заменяет гибель изгнанием **до** dying, combat.death, Вальхаллы, трупоедства и death-trigger. `ZoneManager::toGraveyard()` дополнительно защищает прямой переход. Обычные существа сохраняют прежний путь.
- `ZoneManager::exileIncorporeal()` использует штатный `toExile()`, очищает ограничения от ушедшего источника и пересчитывает броню. Сохраняет последние 20 уведомлений с индивидуальными последовательными ID.
- `InfoPanel::renderIncorporealNotices()` использует существующие `Panel`, `battle-notices.js`, кнопку «Понятно» и механизм восстановления после AJAX. Сообщение содержит имя карты и причину; закрытие независимо для каждого зрителя. Новых JS/CSS/компонентов нет.
- `BattleScreen` добавляет ссылку обычного движения на занятую клетку при обычном выборе бестелесного; явно объявленный режим атаки сохраняет приоритет атаки. Соседи отображаются существующим стеком, стрелками поля/панели и выбираются по instanceId.
- Журнал не получает ложного `combat.death`. Полный replay этой новой механики не сертифицирован: используется существующая граница `Recorder::unsupported('incorporeal_exile')`; живое состояние и AJAX остаются авторитетными. Не заявляется поддержка полного воспроизведения новых правил.

## Остальные ограничения правила 89

| Ограничение | Состояние |
| --- | --- |
| Добивание | Уже было в `CardStats::canExecuteTarget()` и серверной ветке execute в `ActionResolver`; сохранено и проверено. |
| Допустимые симбиоты | Уже было в `SymbioteProcessor::hosts()`/`refresh()`: телесный симбиот не садится на бестелесного хозяина. Сохранено; прикреплённые бестелесные не обязаны отделяться. |
| Отравление | Добавлен запрет в `Engine::applyPoison()`, списке целей poison_target и серверном `ActionResolver::resolvePoisonTarget()`. |
| Лечение | Добавлен запрет восстановления HP в `CardHealing`, включая full; `StitchRevival::legalHealTarget()` исключает такие цели. |
| Вампиризм | `DamageResolver` не запускает его для бестелесного источника/жертвы. |
| Трупоедство | Бестелесная жертва не вызывает гибель и соответствующий эффект; бестелесный источник не ставит трупоедство в очередь и не лечится немедленным трупоедством. |

Полная поддержка правила 89 **не заявляется**. Не выполнялся массовый пересмотр прямых присваиваний HP и исторических/сохранённых состояний: отдельного аудита требуют регенерация (`Engine::applyRegeneration`, `TurnPhaseProcessor::executeRegen`), перенос ран (`WoundTransferProcessor`), уже существующий яд и его усиление (`resolvePoisonBoost`), уже поставленная очередь трупоедства при изменении свойств. Получение дополнительных жизней намеренно не запрещается (`TemporaryHealth`, start.get_hp). Специфические свойства конкретных карт и уменьшение немагических повреждений автоматически из одного флага не добавлялись. Бот с новым свойством отдельно не сертифицирован.
