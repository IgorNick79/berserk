# Бон и Берроу — реализация и проверка

Текущий порядок эффектов исправлен после ручного тестирования: оба дополнительных выбора открываются после полного завершения сражения. Подробный аудит и результаты исправления: [bon_and_berrow.post-combat.md](bon_and_berrow.post-combat.md).

Ветка: `codex/bon-and-berrow`. Основа: `main`, `250e717` (совпадает с `origin/main` после fetch).

## Аудит и границы проверки

До реализации изучены `CardStats`, `ActionResolver`, `StrikeResolver`, `DamageResolver`, `InstantProcessor`, реестр ChoiceHandler, передача монет Хроноса, Вальхалла, эффекты Шакси и UI поля/InfoPanel.

Локальная БД недоступна: read-only запрос через существующий `config/db.php` основного checkout завершился ошибкой подключения, в том числе при запуске вне sandbox. Поэтому **ukid не установлен**, реальные prop Пустотника, Хроноса, Етуна и Мантикоры из БД не сверены и обновление БД **не выполнено**. Старый prop Бона и Берроу не использован. `docs/05_cards.md` подтверждает настройки Пустотника `coins.max_value`, `coins_receive_deny`, а также общий `ignore` Мантикоры. Сценарии chronos/ogre, перечисленные в старом `docs/project.md`, в текущем checkout отсутствуют.

Для окончательной проверки данных на доступной БД нужен read-only запрос:

```sql
SELECT ukid, name, prop FROM cards
WHERE name IN ('Бон и Берроу', 'Пустотник', 'Хронос', 'Етун', 'Мантикора', 'Ост');
```

Особенно нужно сверить фактические ignore Етуна/Мантикоры. Тесты подтверждают обход через существующий `ignore` (список и объект), но не заменяют проверку записей этих карт. Полностью игнорирующая `zoa` атака не предлагает монетку. Игнорирование только `zoan` не снимает `zoa`: семантика конкретных ключей сохраняется. Для конфигурации защиты `zoan`/`zoal` также учитывается тип атакующего.

## Реализация

- OVA задаётся числом `1`, броня — существующим объектом `{ "value": 1 }`; `has_armor` используется существующим UI.
- Монетки — только `CardInstance::coins`; максимум 1 через `coins.max_value`, запрет передачи через `coins_receive_deny`, `save_coins` отсутствует. Хронос уже проверяет `CardStats::canSpendCoins` и отвергает такую цель без расходования своей монеты. Дополнительно закрыты внешние пути через Вальхаллу и Шакси; собственные эффекты этих карт сохранены.
- Собственное получение использует те же числовое состояние, лимит и `syncCoinBonus`. Параметры `source` и `selfEffect` разрешают исключение только для собственного экземпляра; глобальный запрет не снимается.
- `coins_required: 0` проверяется сервером и UI. Активная способность делегирует существующему `uchr` с `value: 2`, обычной геометрией, промежуточной картой, защитами, бронёй и расходом действия. Карта закрывается до разрешения. После полного завершения сражения, подтверждений результата и обязательных continuation открывается необязательный выбор монетки; возобновление выбора не повторяет удар. Монетка доступна и после блокирования УЧР, поскольку её получение не обусловлено нанесением ран.
- Разряд запускается по разнице HP непосредственно до/после `applyDamage`, а не по результату кубика или исходной величине удара. Учитываются простой/ответный, особый, магический удары и УЧР. Выстрел, метание, разряд и другие источники не запускают эффект.
- `on_wounding_strike` хранит `strike: {weak:1,medium:2,strong:2}` и `range:3`. Цели выбираются стандартным `BattleHelper`, исключая умирающих и мёртвых. Сохраняются правила запрета дальней атаки по соседям, перехвата, полёта и дальности. Нет допустимых целей — нет pending.
- Выбранный разряд выполняется существующим `resolveDamage`, со стандартным кубиком, защитами, снижением урона, реакциями и перенаправлением. Монетка и второе действие не расходуются. Разряд имеет отдельный стандартный результат после завершения основного сражения. Полный итог исходного сражения, включая ответный удар и after-инстанты, сохраняется в `coin_post_combat_history`. Это проверено также для reload, перенаправления разряда и вложенного обязательного сражения из after-инстанта.
- Блокирование монеткой открывается перед кубиками по фактической цели/защитнику. Новый ChoiceHandler использует существующий реестр, сериализуемый pending и PanelSpec. Подтверждение расходует монетку и завершает заблокированный удар без ран, ответного удара и бросков. Отказ продолжает исходный расчёт и больше не предлагает блокирование этого удара.
- Каждому pending присвоен уникальный идентификатор: старый запрос не может подтвердить следующий выбор. Проверяются владелец и актуальность. Число монеток остаётся единственным состоянием режима карты; маркеры завершения эффектов хранятся только в контексте конкретного сражения.
- UI переключает УЧР, показывает текущее условие разряда и число монеток. Разряд отсутствует среди самостоятельных действий. InfoPanel содержит требуемые кнопки и результат дополнительного разряда/блокирования.

## Полный prop для замены

Машиночитаемый файл: `docs/cards/bon_and_berrow.prop.json`. После определения ukid нужно заменить **целиком** поле `cards.prop` этой записи; JSON не следует сливать со старым prop.

```json
{
  "ova": 1,
  "armor": {
    "value": 1
  },
  "has_armor": true,
  "coins": {
    "max_value": 1
  },
  "coins_receive_deny": true,
  "actions": [
    {
      "key": "row_strike",
      "name": "Удар через ряд на 2; можно получить монетку",
      "type": "uchr",
      "value": 2,
      "coins_required": 0,
      "optional_self_coin": 1
    }
  ],
  "on_wounding_strike": {
    "min_coins": 1,
    "type": "discharge",
    "name": "Разряд при ударе",
    "strike": {
      "weak": 1,
      "medium": 2,
      "strong": 2
    },
    "range": 3
  },
  "coin_block": {
    "cost": 1,
    "defense": "zoa",
    "types": [
      "strike",
      "uchr",
      "tap",
      "magic"
    ]
  }
}
```

## Изменённые файлы

- `src/Core/CoinAbilities.php` — условия по монеткам, собственное получение, сериализуемые выборы и продолжения.
- `src/Core/Choice/CoinAbilityChoice.php` — интерфейс выбора и маршрутизация.
- `src/Core/Choice/ChoiceRegistry.php` — регистрация обработчика.
- `src/Core/ActionResolver.php` — интеграция УЧР/особых ударов/разряда, сохранение родительского результата, внешнее получение Шакси.
- `src/Core/StrikeResolver.php` — блокирование до кубиков, фактические раны и защита от повторного apply.
- `src/Core/BattleHelper.php` — доступность УЧР по монеткам.
- `src/Core/ValhallaProcessor.php` — запрет внешнего получения.
- `src/View/Screen/BattleScreen.php` — текущие способности и подсказки.
- `src/View/Screen/Battle/InfoPanel.php` — результаты блокирования/разряда.
- `tools/test_bon_and_berrow.php` — тесты без зависимости от БД.
- `docs/cards/bon_and_berrow.prop.json`, этот отчёт.
