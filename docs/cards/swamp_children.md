## Предварительный аудит

До изменений изучены CardStats (hasDefense/isDefenseIgnored/isDisabled), StrikeResolver (declare/resolve/apply, защитник, ответ, ACK), ActionResolver (УЧР, особые удары, продолжение после coin_block), InstantProcessor (redirect → dice → power → value → setter → wounds), ChoiceRegistry и обработчики TeleportTargetChoice/ForcedDirectionalMoveChoice/CoinAbilityChoice/CellMarkerChoice, сериализация GameState/CardInstance, TurnProcessor, BattleHelper, MovementResolver/MovementContext/MovementEffectResolver/ForcedMovementResolver, BattleScreen и InfoPanel.

`zoa` — универсальная защита, `zoan` относится к наземному атакующему, `zoal` — к летающему. `ignore` проверяется по конкретному ключу: список и объект поддерживаются CardStats::isDefenseIgnored. Игнорирование одного `zoan` или `zoal` не обходит `zoa`.

Прыжок в проекте использует манхэттенскую дальность, границы 6×5, занятость клетки и блокирующие маркеры. Дополнительно учитываются rooted, сеть, лимит движущихся существ, запрет ухода от обязательной цели. Принудительное перемещение проверяет наземное живое существо, rooted, свободную конечную клетку, костёр и лимит движения. Соседство включает диагонали через ZoneManager::areAdjacentFieldCards.

## Полный JSON новой механики

```json
{
  "first_strike_jump": {
    "defense": "zoa",
    "range": 2,
    "pull_adjacent_enemy": true
  }
}
```

Машиночитаемый файл: `swamp_children.prop.json`. Это весь подготовленный prop механики. При подключении к реальной записи нужно добавить только `first_strike_jump` к существующему объекту, сохранив остальные свойства. Полный существующий prop неизвестен из-за недоступности БД; автоматического импорта/обновления карты нет.

`first_strike_jump` означает первый входящий удар чужого существа за ход и автоматическое блокирование через указанный ключ защиты. `range` задаёт обязательный прыжок, `pull_adjacent_enemy` — обязательное последующее перемещение соседнего существа противника по выбору его владельца. Текущая клетка всегда исключается общей геометрией прыжка. Эти параметры не зависят от ukid.

## Учёт и боевой lifecycle

FirstStrikeJump фиксирует `flags['trigger_used_this_turn:first_strike_jump']` **до** проверки ignore. Значение содержит `battle.turn` и активного игрока, поскольку существующий battle.turn считает полные раунды. Используется существующий префикс сбрасываемых TurnProcessor флагов. Stamp дополнительно исключает перенос использования между полуходами. Флаг сериализуется вместе с картой. Свои удары, атаки несуществ и действия shot/throw/discharge/impact/execute/cast флаг не расходуют. Учитываются обычный удар, УЧР, особые tap/magic и фактически назначенный ответный удар; летающая карта тоже считается существом.

Для обычного удара проверка стоит в resolve после выбора фактического защитника и окна redirect, до монетного блока и кубиков. Успешный блок применяет пустую таблицу существующим StrikeResolver::apply: действие атакующего учитывается один раз, ран и ответа нет, эффекты успешного удара не запускаются. Сохраняется обычный strike со state=results, без дополнительных бросков и без повторного resolve. Особые удары получают аналогичный нулевой результат до броска. При блокировании ответа сохраняется урон уже нанесённого основного удара, блокируется только ответ.

Исходный strike остаётся в battle на протяжении обоих выборов. Нового сражения или рекурсивного запуска исходного удара нет. После окончания выборов игроки завершают сохранённый результат обычными ACK; после этого продолжается существующий порядок after-инстантов. Если прыжка или второго выбора нет, результат сразу доступен для обычного завершения.

## Два обязательных выбора и перемещение

Используется зарегистрированный ChoiceHandler и `battle.pending_first_strike_jump`, последовательно меняющий stage с jump на pull. Первый stage принадлежит владельцу защищаемой карты, второй — его противнику. У каждого stage свой случайный `choice_id`; отсутствие/несовпадение идентификатора и неверный владелец отклоняются сервером. cancel_pending не поддерживается, другие игровые команды во время выбора блокирует существующий Engine.

Первый pending содержит snapshot допустимых клеток, дальность и исходные row/col. При подтверждении заново проверяются карта, владелец, исходная позиция и допустимость клетки. MovementResolver::triggeredJump использует общую геометрию BattleHelper и общий executeJump с обычным прыжком, сохраняя movement effects. Закрытость и уже использованное движение не требуют открытия/нового действия; сеть, rooted и остальные ограничения сохраняются. move, closed и moved_this_turn не расходуются. Лимит движущихся существ учитывается общим механизмом.

Исходная клетка записана непосредственно перед прыжком и переносится во второй stage. Кандидаты ищутся относительно этой клетки общим определением соседства. Включаются только собственные живые наземные существа противника, которые ForcedMovementResolver разрешает переместить на освободившуюся клетку. Для единственного кандидата тоже показывается обязательный выбор. При нескольких — имя и позиция позволяют различить карты. Во время подтверждения проверяется принадлежность snapshot и актуальному списку, затем используется ForcedMovementResolver::move; действие и закрытость существа сохраняются.

Оба stage представлены кнопками в InfoPanel и подсветкой допустимых клеток/существ непосредственно на поле только у владельца выбора. Отказ отсутствует. Состояние защиты отображается в панели выбранной карты, блок — в результате сражения.

После успешной команды предыдущий stage удаляется или заменяется stage с новым ID. GameState::toArray/fromArray сохраняет pending, snapshot, origin, stage, ID, карту и боевой результат. Повтор старого запроса не может подтвердить следующий stage, повтор после завершения отклоняется. Флаг first_strike_blocked также делает повторный resolve заблокированного результата инертным.
