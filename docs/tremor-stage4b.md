# Скелетный червь — этап 4Б

Продолжение операции хранится в pending_incarnation.worm_operation. Стадии: destroy → effects (с дочерними обязательными выборами) → destroy следующей исходной карты → placing → complete. Сохраняются ID операции/Червя/маркера, координаты, исходный список экземпляров, индекс, задания эффектов, счётчик выборов и признаки размещения/расходования.

WormIncarnation управляет только последовательностью. Уничтожение выполняется Engine::forceDeath / DamageResolver::resolveDeath. В адресной ветке triggerOnDeath задания сохраняются в операции, а исполняются DamageResolver::executeWormDeathJob через штатные applyDeathEffect и CardHealing. Вложенная смерть добавляет свои задания перед оставшимися заданиями внешней смерти. Карты сохраняют dying и положение до завершения обязательных продолжений. После каждого успешного дочернего запроса Engine продвигает операцию. CombatContinuation::busy не используется.

Предсмертный выбор содержит operation_id и choice_id. Завершение проверяет владельца, операцию, контекст strike и идентификатор выбора. Проверенный выбор удаляется до исполнения его эффекта, поэтому вложенный выбор не может быть удалён внешним завершением. Обычные смерти/удары используют прежнюю ветку; общий контракт pending_choice не менялся. UI выбора предоставлен существующим IncarnationChoice, InfoPanel не изменялся.

checkGameOver пропускает только проверку устранения при активной операции текущего Червя и явно перечисленных стадиях destroy/effects/placing. Сдача устанавливает терминальное состояние немедленно. На стадии complete, после размещения и удаления одного зарезервированного маркера, проверка победителя вызывается снова. Терминальный бой не возобновляется.

Tremor::incarnationCells теперь включает занятые клетки. Стабильный ID маркера резервируется при начале операции; маркер расходуется после штатного размещения. Если эффекты снова заселили клетку, новые находящиеся на ней экземпляры также обрабатываются до размещения. Проверка блокирующего костра сохранена.
