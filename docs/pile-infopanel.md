# Просмотр кладбища/изгнания в InfoPanel

- Вне сражения списки перенесены из области под полем в правую InfoPanel.
- Заголовок указывает зону, владельца и количество карт. Крестик закрывает список.
- Открытие списка закрывает выбранную карту поля. Плашки используют `PrepareUi::card`, как история выбора драфта.
- Каждая плашка ведёт к конкретному экземпляру карты. Просмотр карты содержит «К списку»; обычные атаки и перемещения для карт кладбища/изгнания не показываются. Выбор другого владельца/зоны и закрытых карт колоды по URL не разрешается.
- Длинные списки получают локальные страницы с чипами. Вместимость рассчитывается по размеру InfoPanel, размеру плашек и маркерам. Страница сохраняется при AJAX snapshots; никакой записи состояния партии для просмотра нет.
- Обязательный контекст действий остаётся отдельным блоком: ссылки инкарнации, Вальхаллы и другие pending-решения не заменяются списком.
- Стек инстантов и результат разрешения инстантов получили такой же режим показа, как сражение: начальная выбранная карта скрыта, контекст стека открыт. Можно отдельно осмотреть карту и вернуться кнопкой «Закрыть». Во время стека обычные ссылки атаки/перемещения не предлагаются; механика и её проверки не менялись.
- Сочетание открытого сражения со списками оставлено прежним до решения пользователя: приоритет и представление сражения не меняются, просмотр стопки остаётся под полем.

Изменены `BattleScreen.php`, `Battle/InfoPanel.php`, `battle-ui.js`, `global.css` и версия скрипта в `battle.tpl`. Ключи AJAX-фрагментов сохранены; вне сражения `pile_reveal_html` пуст, список находится внутри `info_panel_html`.

Проверки: 75 PHP assertions (`tools/test_pile_panel_ui.php`), 462 браузерные проверки (`tools/test_pile_panel_browser.cjs`) для обоих зрителей на ширинах 1600/800/375. Проверены все четыре стопки, выбор/возврат карты, отсутствие обрезанных строк, сохранение страницы при snapshot, доступность инкарнации/Вальхаллы, открытие и осмотр карт в стеке. Представления не меняют сериализованное игровое состояние.

Прошли существующие `test_battle_snapshot_renderer.php`, `test_combat_panel_ui.php`, `test_combat_panel_browser.cjs` (оба игрока, 1600/800/375) и пагинация летунов. В snapshot-тесте обновлены ожидания: открытие стопки сбрасывает выбор карты поля, список больше не находится в `pile_reveal_html`.

Старый `test_battle_stage1b_ui.php` ожидает единственный текст «Сдаться» во всём footer, но считает также существующий noscript fallback. Этот участок не менялся в задаче; устаревшая проверка не исправлялась вместе с новым интерфейсом.

Запуск: `php tools/test_pile_panel_ui.php`. Для браузера задать `PHP_BINARY`, при необходимости `PLAYWRIGHT_MODULE` и `BROWSER_EXECUTABLE`, затем `node tools/test_pile_panel_browser.cjs`. Опционально `PILE_SCREENSHOT_DIR` сохраняет скриншоты. БД для этих тестов не требуется.

Уточнение оформления: заголовок получил фон и границу в стиле InfoPanel; плашки всегда расположены в двух колонках, включая мобильный экран. Закрытие использует предоставленный `www/assets/images/battle/close.png` с подсказкой «Закрыть» и явным `pile=`: существующий AJAX-обработчик закрывает список без навигации документа. Дополнительные браузерные проверки подтверждают неизменность документа, пустую стопку в параметрах AJAX, фон заголовка, изображение, подсказку и две колонки.
