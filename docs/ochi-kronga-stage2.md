## Подключение и контракт

Конфигурация способности в prop карты:

```json
{"direct": true, "zoz": true, "on_ally_action_sequence_open": {"filter": "forests"}}
```

UKID и стихия источника не зашиты в код. direct/zoz остаются самостоятельными свойствами.
Карточные данные и БД не изменены: конфигурацию необходимо добавить отдельно при разрешённой интеграционной проверке.

ActionResolution::resolve() синхронно передаёт исходное уведомление в OchiKronga::onResolution().
Процессор не читает диагностический массив notifications, Recorder или БД для определения результата.
Используются native type, origin, outcome, hit, hp_restored, actor_id, owner, actor_type, element и sequence.
Сначала классифицируется действие, затем исполнитель; первичного отбора по forests нет.
Поэтому результативное действие нелесного существа доходит до обработчика и очищает префикс.

## Состояние

В сериализуемом flags каждого экземпляра:

```json
{"ochi_kronga": {"period": "host:timer:7", "sequence": ["strike", "shot"], "uses": 0, "last_sequence": 15}}
```

sequence — префикс максимум из двух разных подходящих типов; uses — число успешных открытий (0–2).
last_sequence — номер доставки, защищающий от повторной обработки; ID действия не задаёт порядок вложенных результатов.
period использует владельца и сохранённый TurnTimer.period_id. Для старых состояний без таймера есть fallback owner+turn.
Начало собственного хода после TurnTimer.prepare сбрасывает состояние один раз; resume того же периода не сбрасывает.
Старый таймер во время завершения предыдущего хода не считается новым собственным ходом.
Выход из игры через ZoneManager и removeCard очищает состояние, включая счётчик; возвращённый экземпляр начинает заново.
Переход поле/летающая зона не очищает состояние. Источник должен находиться в игре, иметь HP > 0 и не dying.

## Классификация фактических результатов

| Native событие | Обработка |
|---|---|
| strike / shot, hit=true | Кандидат, в том числе с нулевым итоговым уроном |
| heal, hp_restored >= 1 | Кандидат, включая пассивное лечение и вампиризм |
| miss / blocked / cancelled / no_effect, лечение 0 | Игнорирование без сброса |
| move / jump / teleport / teleport_target / forced_move | Игнорирование для любых исполнителей |
| answer или origin=response | Игнорирование |
| Технические/system продолжения | Игнорирование |
| bomb_shot, hit=true | Прерыватель; не преобразуется в shot. Орк-бомбардир нелесной |
| Прочие самостоятельные выполненные действия | Прерыватель, включая ручное открытие |
| Прочие пассивные последствия | Не самостоятельные действия, игнорируются |
| dive | Самостоятельное составное действие прерывает; дочернее перемещение игнорируется |

Кандидат продолжает цепочку только для другого собственного лесного creature/fly в собственный ход.
Любой результативный неподходящий исполнитель очищает её, включая нелесных, чужих, сам источник и несуществ.
Повтор типа очищает старый префикс и начинает новый текущим событием.
Третий разный тип очищает префикс и открывает закрытый источник через штатный Engine::openCard при uses < 2.
Если источник уже открыт, openCard не вызывается и лимит не расходуется; завершённая тройка всё равно очищается.
Автоматическое открытие не создаёт самостоятельного уведомления и не прерывает обработку других экземпляров Очей.
Несколько экземпляров независимо видят одно исходное событие и могут открыться одновременно.
