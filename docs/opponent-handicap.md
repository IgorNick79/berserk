# Фора сопернику

## Итог аудита и уточнение семантики

Deal получает исходные ресурсы в `PrepareProcessor::dealCards()`: 24 золота / 22 серебра для стороны 1 и 25/23 для стороны 2. `ResourceCalculator` считает расходы, штраф стихий, специальные скидки/доплаты и покрытие нехватки обычного серебра золотом. Эти правила не менялись.

LuckTest не проходит Deal: он генерирует готовые отряды, а `resources` обоих игроков остаются нулевыми. Буквальная прибавка в это поле не усилила бы отряд. После аудита пользователь уточнил требование: **добавлять фору второму игроку**, а не уменьшать отряд хоста. Для LuckTest это реализовано добавлением золота и серебра к целевым валютным суммам уже сформированного второго отряда.

## Хранение и применение

Общие поля: `GameSettings.battle.handicap_enabled`, `handicap_gold`, `handicap_silver`. Они проходят LobbyWizard → RoomSetup → `lobby_rooms.setup_json` → MatchCreator → настройки GameState. Выключенный флаг даёт эффективные 0/0, даже если в JSON сохранены ненулевые ползунки. Старые JSON без новых полей получают false/0/0 через существующие defaults. Схема БД не меняется.

Второй шаг мастера содержит общий раздел «Основные настройки», галочку и два независимых ползунка 0–5. По умолчанию флаг выключен, оба значения 0. Скрытие ползунков сохраняет их значения. Используются существующие `settings-range` и `wizard-check`.

**Deal:** после присваивания базового бюджета прибавка применяется только к ключу `player`, то есть сопернику хоста, независимо от выбранной стороны и первого хода. При повторной инициализации сначала заново присваивается база, поэтому прибавка не накапливается. GET/синхронизация не начисляют ресурсы.

**LuckTest:** сначала выполняются прежний подбор общей стоимости и, если включена, балансировка валют. Затем отдельный ограниченный проход подбирает только отряд соперника под `его исходное золото + фора` и `его исходное серебро + фора`. Изменения принимаются при уменьшении расстояния до этих целей и без уменьшения исходной суммы любой из валют. Хост не меняется. Количество карт и обязательные Debug-карты сохраняются; при включённом балансе специальных карт сохраняется их категория. Балансировка не запускается повторно после форы и не компенсирует преимущество. Режимы Roll, Place и Battle используют одну генерацию.

## Примеры

Deal при стороне 2 соперника:

| Фора | Бюджет соперника | После повторной инициализации |
|---|---|---|
| 0/0 | 25/23 | 25/23 |
| 2/0 | 27/23 | 27/23 |
| 0/3 | 25/26 | 25/26 |
| 5/5 | 30/28 | 30/28 |
| Выключена, ползунки 5/5 | 25/23 | 25/23 |

Хост стороны 1 во всех этих случаях имеет 24/22. Эти значения проверены в памяти и фактические бюджеты обеих сторон — через HTTP/БД с повторными запросами страниц Deal.

Пример настоящего генератора на тестовом каталоге с ценами 3/5/8/10, одинаковый seed, по 6 карт:

| Фора | Хост: золото/серебро | Соперник: золото/серебро |
|---|---|---|
| 0/0 | 30/15 | 29/16 |
| 2/0 | 30/15 | 31/16 |
| 0/3 | 30/15 | 29/18 |
| 5/5 | 30/15 | 34/20 |

В последнем случае серебряная цель 21 достигнута не полностью. Это допустимый приблизительный результат; количество карт не меняется. Полностью обязательный отряд может остаться без изменений — Debug-карты не заменяются ради форы.

## Проверки

- 315 изолированных HTTP/БД-проверок: комбинации 0/0, 2/0, 0/3, 5/5, выключенная 5/5; точный бюджет Deal; отсутствие повторной прибавки; все три старта LuckTest × оба положения валютного баланса; сохранение параметров; количество карт, неотрицательные ресурсы, повторные запросы; создание Grid/Solomon/Sealed; старые комнаты и неверные значения.
- 46 браузерных проверок: выключенные defaults во всех пяти режимах, раскрытие, границы ползунков и output, сохранение значений при скрытии, отсутствие переполнения на 360 px. Скриншоты desktop/mobile подготовлены.
- 186 прежних проверок LuckTest, 73 проверки валютного баланса, отдельный `test_opponent_handicap.php`: Deal без накопления, независимость форы от баланса, неизменность хоста, выключенная фора, количество и обязательные карты.
- PHP lint, синтаксис JavaScript и `git diff --check` пройдены. В логах успешного HTTP-прогона ошибок PHP/SQL нет.

Первая попытка браузерного теста остановилась из-за неоднозначного локатора `data-step=1` в тесте; локатор ограничен кнопкой, полный прогон повторён успешно.

## Ограничения

LuckTest использует существующую классификацию стоимости карт по elite/ordinary; правила расходов Deal туда не переносятся. Подбор ограничен 16 заменами на свободную карту, точное достижение форы не гарантируется. Невозможная фора не приводит к ошибке допустимого отряда. Production-каталог не проверялся; данные и аккаунты стенда тестовые. Общая отложенная HTTP-регрессия боевого таймера остаётся отдельной незавершённой проверкой.

Commit, push, deploy и миграции рабочей БД не выполнялись.
