## Поведение

1. При старте выбирается доступный Махинатор обычным существующим маршрутом. В pending записывается его instanceId в reorder_source_id.
2. После reload reorderCard проверяет именно этот экземпляр: владелец, поле/flying, жизнь и effectiveProp.prophecy_reorder. Другой доступный Махинатор не подменяет источник.
3. Подавление искателя само по себе не запрещает способность другого Махинатора.
4. Если источник подавлен либо недоступен, новые перестановки не выполняются. Вызывается существующий TurnProcessor::closeProphecy, включая обычную финализацию карт и существующий возврат управления.
5. Та же финализация применяется только к активному legacy reorder_mode без достоверного reorder_source_id. Источник по полю не угадывается.
6. Уже выставленные порядки карт сохраняются. Для остальных карт выполняется существующая техническая очистка in_prophecy_pending и штатная обработка идентификаторов карт внизу колоды.
7. Повторные reorder_card и reorder_start после такой финализации не выполняют перестановку, поскольку соответствующего pending уже нет. Обычные pending пророчества без reorder_mode не затрагиваются.
