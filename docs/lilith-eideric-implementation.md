# Задача 200: Лилит и Эйдерик

Реализация без ukid, БД/рабочие prop/InfoPanel не изменены. Без commit/push. Предлагаемый prop: lilith-eideric.prop.json.

## Механика

GraveRitual подключён адресной задачей TurnPhaseProcessor в начало собственного хода. ProphecyProcessor::peek определяет верхнюю карту; ZoneManager::toGraveyard сохраняет штатные события попадания на кладбище. После дочернего pending операция продолжается через Engine. Классы проверяются независимо; обе ветки выполняются для демона-нежити. Кандидаты нежити собираются после перемещения. Одна цель выбирается автоматически, несколько — GraveRitualChoice. turn/source ID исключает повторный сброс карты.

Общий IncarnationTokenProcessor::grant переиспользуется Талионом и ритуалом. Без способности incarnation создаётся только value, без threshold/open, глобальные проверки инкарнации сохраняются. Регрессия Талиона обновлена: прежняя проверка threshold=0 заменена отсутствием threshold в соответствии с согласованным правилом.

class_turn_bonuses хранит владельца, ход, класс, strong и ova. CardStats::getAbilityBonus и getOva вычисляют бонус динамически, включая новых демонов. Бонус удаляется при завершении собственного хода; UI показывает сильный удар +1 и ОВА +1 через ActiveCardEffects.

PairedRanged проверяет существование пары различных целей штатным поиском для каждого типа. Первый список исключает цели без допустимой пары. Оба выбора допускают отмену без поворота. После двух валидированных целей источник поворачивается один раз, serializable paired_ranged хранит index, selected, jobs и ID. ActionResolver::triggeredRanged переиспользует resolveDamage для discharge/throw. Первый эффект полностью завершается до второго; актуальная допустимость второго проверяется повторно, исчезнувшая цель пропускается. DeathEffectContext адресно поддерживает очередь смертей операции; идентификаторы предсмертных выборов проверяются штатным resolver. Отложена только проверка устранения существ при активной операции, затем вызывается checkGameOver.

UI: GraveRitualChoice и PairedRangedChoice в ChoiceRegistry, стандартные radio-поля и переключение свои/чужие, default enemy для атаки. BattleWaitResolver определяет владельца выбора; глобальные правила таймера не менялись. ЗОТ — zot:true.

## Проверки

tools/test_lilith.php читает debug/scenarios/lilith.json: 47 проверок. Проверены четыре сочетания классов, штатное попадание на кладбище, независимые ветки, жетон без способности/с ней, отсутствие искусственного порога, идемпотентность ритуала; реальный Engine::action с разрядом и метанием, собственная вторая цель, подтверждения результатов, повторные команды, JSON-восстановление; смертельный разряд с предсмертным выбором, исчезновение второй цели и пропуск метания; реальный end_turn -> начало собственного хода, бонусы strong/ova, поздний демон и сброс в конце хода.

Дополнительно прогоняются Талион, инкарнация Червя, Алвалинд, Ведунья, combat instant phases, effective features, pending/wait/timer.

## Непроверенные взаимодействия

Два HTTP-клиента и production-маршрут не запускались. Нужна ручная проверка визуального отображения и выбора целей. Не выполнен исчерпывающий перебор всех 70 пунктов задания: в частности все сочетания защит, отмены обоих этапов, несколько источников ритуала, вложенное лечение, реакции на жетон, совместный pending Дрожи/ритуала, конкурентные HTTP-запросы и специальные инстанты. Указанные случаи нельзя считать подтверждёнными только успешным базовым прогоном.
