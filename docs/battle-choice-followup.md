# Исправления выбора существ и инстантов в main

Основа: `main` на `17606cc`. Механики Stage 2A/2B и конфигурация Короля-жреца
не переносятся в main этим изменением. БД, сохранения, Recorder не изменены.

## Интерфейс

* Окно/предложение инстантов находится после основного содержимого InfoPanel,
  непосредственно над footer с завершением хода, отделено border-top.
  Уведомления и обновления панели учитывают новое расположение.
* Результаты impact не показывают кубики: этот маршрут их не бросает.
  Это исправляет отображение «Потери памяти» при последующем использовании
  интерфейса вместе с веткой, реализующей способность.
* `CreatureChoice` задаёт общий вид целей: имя, координаты справа, без текущих HP.
  Применяется к обычным action-целям и зарегистрированным формам выбора
  target_id / target_ids[] / card_id для существ на поле.
* Старые списки кнопок instant/combat pick, возрождения и выбора цели
  посмертной способности преобразуются в radio с прежними ID, командами
  и возможностью отмены там, где она уже была.
* Для radio с целями обеих сторон есть JS-переключатель «Свои / Чужие».
  Сторона и выбранное существо сохраняются при polling. Скрытая сторона
  не отправляется формой. Без JS доступны все исходные варианты.
  Checkbox не фильтруется по стороне, чтобы не мешать выбору нескольких целей.
* Подробности выбора карт кладбища (например, число жетонов инкарнации)
  остаются в существующих формах; они не заменяются без разбора назначения.
* Дверь измерений использует общий CellMarkerPicker, как телепортация Крондака:
  сторона, ряд, столбец, подсветка на поле; без JS остаются ссылки на клетки.
  Передаются исходные системные координаты через прежний choose_teleport_cell.
* Активная связь `flags.memory_loss_sources` отображается как «Потеря памяти»
  в списке эффектов звёздочки. Добавлена только проекция UI, без механики
  подавления в main.
* Блок вампиризма использует фон и текст выбранной темы, сохраняя контраст.

## Допустимость инстантов в сражении

Общий фильтр в InstantProcessor проверяет фактического защитника
(`defender_id`, иначе `target_id`) и атакующего. Занятое существо не использует
боевой инстант; перенаправление сохраняется как исключение. Специальное окно
Бешеного мага в StrikeResolver сохраняется. Ограничение перенаправления в
приказе Матриарха также сохраняется.

Проверки применены при построении списка, при серверном объявлении,
при подтверждении выбранной цели и перед исполнением элемента боевого стека.
Лунная баньши, сама ставшая защитником, не может применить боевой плач.
Третье существо с той же способностью может помочь.

Turn-инстант защитника разрешён перед сражением: источник закрывается по
обычной оплате, после чего бой продолжается против закрытого существа.
Если Ледовый страж закрывает атакующего, прежнее продолжение отменяет бой.

## «Пас», затем «ОК» — пока без изменения

Это два разных действия: Пас завершает набор стека; ОК подтверждает результат
и возобновляет продолжение. После добавления инстанта passed сбрасывается,
а автоматическая проверка отсутствия вариантов вызывается на пути передачи
приоритета. Поэтому последний единственный инстант может требовать Пас.
В дальнейшем можно автоматически завершать набор при отсутствии легальных
вариантов у обеих сторон и оставлять одно ОК. Такое изменение в этот пакет
не включено.
