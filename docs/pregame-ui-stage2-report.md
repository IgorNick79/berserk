# PreGame UI — Stage 2: Screen Integration

Работа выполнена в существующей ветке `codex/pregame-ui-audit`. Stage 1 и его review-исправления сохранены. Дополнительные ветки, рабочие копии, зависимости и коммиты не создавались.

## 1. Изменённые файлы Stage 2

- `src/View/Ui/PreGameLayout.php`: добавлена сборка существующих экранов через тот же layout и прежний контракт слотов.
- `src/View/Ui/PrepareUi.php`: небольшой адаптер информации об уже разрешённой выбранной карте.
- `src/View/Screen/ModeScreen.php`: заголовок вынесен из формы в header панели.
- `src/View/Screen/DraftScreen.php`: новая карточная панель, привязка preview к позиции/ukid/версии, разрешённые шаблоны стека Solomon, форма только активному игроку.
- `src/View/Screen/ViewScreen.php`: информация справа, действия сайдборда в Main; поддержка старых системных колод без экземпляров.
- `src/View/Screen/DealScreen.php`: проверка принадлежности выбранной карты своей руке/отряду; цена, условия и действия найма остаются в Main.
- `src/View/Screen/PlaceScreen.php`: сведения справа; после подтверждения не выводятся ссылки расстановки.
- `src/Core/DeckView.php`: аддитивные поля представления `descr`, `rarity`, `element_code`, `element_label`; игровые расчёты не изменены.
- `templates/screen/settings.tpl`, `deck_host.tpl`, `deck_wait.tpl`, `view.tpl`, `deal.tpl`, `place.tpl`, `draft.tpl`, `turn.tpl`, `side.tpl`: заголовки стадий и информационные preview убраны из Main; формы и контекстные сообщения сохранены.
- `www/index.php`: подключение существующей оболочки и стабильного CSS rkey ко всем подготовительным экранам; маршрутизация команд не менялась.
- `www/assets/css/pregame.css`: изолированные правила содержимого Main, карточных списков и таймера; старый фиксированный bottom bar становится частью Main и не перекрывает панель.
- `www/assets/js/solomon_selection.js`: просмотр карты независимо от наличия формы и checkbox; сохранены выбор подмножества, decision-scoped sessionStorage и отправка формы.
- `tools/test_pregame_screen_integration.php`, `tools/test_pregame_screen_browser.cjs`: новые изолированные серверные и браузерные проверки.
- `tools/test_solomon_draft.php`, `tools/test_solomon_browser.cjs`: существующие браузерные фикстуры и ожидания актуализированы под Stage 2; игровые assertions не удалялись.
- `docs/pregame-ui-stage2-report.md`: этот отчёт.

`src/View/Template.php`, `templates/page.tpl`, `PreGameCard` и карточный шаблон уже были изменены/созданы на предыдущем этапе; новых изменений в них на Stage 2 нет.

## 2. Подключённые экраны

Все действующие: mode, settings, draft (Grid и Solomon), deck (host/wait), view, turn, side, deal, place. Sealed продолжает использовать settings → view и существующие последующие стадии. Второй layout не создавался.

`PreGameLayout::supports()` перечисляет только подготовительные представления. `renderScreen()` выбирает заголовок, рендерит существующий шаблон Main и передаёт `panel_html` / `timer_html` в прежние слоты. Footer пуст и зарезервирован для Stage 3. Toolbar и «Сброс» сохранены.

## 3. Обновление карточной информации

- Grid использует обычные серверные переходы по ссылке. В preview URL передаются позиция, ukid и версия; несовпадение любого из них сбрасывает preview. Изменившаяся сетка не подменяет просмотренную карту под прежним индексом.
- Solomon использует серверные `<template>` только для публичного текущего стека. Нажатие выводит существующий PreGameCard в правую панель, а у активного игрока также сохраняет прежний смысл переключения checkbox.
- View проверяет выбор по спискам собственной колоды/сайдборда; Deal — по своей руке/отряду; Place — по владельцу и допустимой зоне экземпляра.
- `PrepareUi::information()` передаёт в PreGameCard только одну уже разрешённую карту. Характеристики берутся из статического каталога, а не из модифицированных боевых экземпляров или эффективной цены найма.
- Обработка описаний остаётся в CardDescription::render(). WebP, 8:5, rarity/element и состояния отсутствующих файлов используются из Stage 1.

## 4. Сохранённые игровые действия

Все команды остаются в Main: строки/колонки Grid, подтверждение и пас Solomon, подтверждения стадий, сайдборд, найм/возврат, пересдача, выбор стороны, расстановка и снятие карты.

Deal отдельно показывает имя выбранной карты, эффективную цену, ограничения и специальные пояснения; информационная панель не заменяет этот игровой блок. Существующие pending choice формы сохранены. Серверные проверки очереди, версии, decision_id и легальности действий не изменены.

Ожидающий игрок сохраняет просмотр разрешённых карт. Для Solomon форма и checkbox не выводятся неактивному игроку; JS просмотра работает и без формы. После подтверждения Place ссылки размещения не рендерятся, но просмотр своих карт сохраняется.

## 5. DraftTimer

Перенесён только вывод `timer_html`: из draft.tpl в header PreGameLayout. Сохранены DraftTimer::snapshot(), data-draft-* атрибуты, единственный экземпляр таймера, исходный draft_timer.js, серверные sync URL, версии, отсчёт, перезагрузка при изменении состояния и процессоры таймаутов.

Новый механизм синхронизации не добавлялся. Существующее исключение сохраняется: безлимитный Grid не подключал draft_timer.js и не получил новый polling на Stage 2; безлимитный Solomon продолжает использовать существующий polling. Остальные стадии также сохраняют свой прежний механизм обновления.

## 6. Видимость и безопасность

Полный buildRenderCardInfo остаётся внутренним серверным каталогом и не сериализуется. PreGameCard получает только singleton разрешённой карты. HTML и `<template>` Solomon содержат только текущий открытый стек, а не будущий пул/recycle. История Draft осталась в Main в прежнем виде, без новых кликабельных записей или переключения состояний.

В Deal устранён путь просмотра по одному лишь наличию ukid в полном каталоге: требуется принадлежность запрошенной зоне текущего игрока. Статические сведения старых системных колод получаются из DeckView только после выбора по собственной колоде. Неизвестная стихия в новых полях не заменяется выдуманным кодом neutral.

Новые данные экранируются, описание проходит существующий sanitizer. Изменений GameState, БД, авторизации команд или игрового состояния ради UI нет.

Успешно, ошибок JS нет.

## 8. Обнаруженные проблемы

1. Старый preview Deal совмещал описание и игровые действия — разделён без изменения команд.
2. Старый Deal допускал поиск preview в полном каталоге без проверки своей зоны — добавлена UI-проверка видимости.
3. Старое превью Grid зависело только от позиции — добавлена привязка к идентичности и версии.
4. JS Solomon требовал форму даже для просмотра — просмотр теперь независим.
5. Старый bottom bar был fixed на весь viewport — изолированными стилями возвращён в Main.
6. Старые системные колоды без экземпляров не имели descr/rarity в представлении DeckView — добавлены поля метаданных.
7. Локальная БД недоступна — DB-зависимые блоки не пройдены; используются автономные тесты и фикстуры.

## 9. Ограничения

Изображения карт и PNG редкости отсутствуют в этой рабочей копии; отображаются предусмотренные fallback. Серверные ветки наличия файла покрываются временными файловыми пробами Stage 1; исходные изображения не изменялись.

История, новая статистика, переключатель statistics/card/history, debug-бургер, запреты contextmenu/user-select и мобильная адаптация не реализовывались. Существующая история и существующие счётчики Main сохранены.

Схема идентификации роли first/second и синхронизация вне существующего Draft polling не переустраивались. Пересмотр этих механизмов выходит за пределы Stage 2.
