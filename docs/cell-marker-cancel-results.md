# Отмена Крондака и формат координат результатов

Ветка: codex/battle-ui-coordinates, база 741ec55. Изменения подготовлены к code review; задача не считается принятой автоматически.

## Изменения

CellMarkerChoice::commandTypes() разрешает cancel_pending. apply() отдельно направляет отмену в существующий ActionResolver::cancelPending(), выбор клетки остаётся в chooseCellMarker(). Общая маршрутизация Engine, проверки владельца, приоритет ChoiceRegistry и запрет отмены обязательной атаки сохранены. Новая реализация отмены не создавалась; URL, структура pending и эффекты способности не менялись.

В Coords добавлен renderResult(row, col, viewerKey): безопасный HTML badge `# [I:2]`. Метод проверяет тип координат, использует BattlefieldPosition::display() для преобразования/стороны и rowLabel() для римских цифр. Неверные типы, диапазоны, отсутствующие координаты или неизвестный viewer дают пустую строку. Цвет задают существующие coords--own / coords--enemy, без нового CSS. Старые render() и label() не изменены.

Точечно обновлены четыре структурированных результата InfoPanel:

- cell_marker: `Разжигание костра: # [I:2]`;
- teleport: имя цели и сообщение о перемещении сохранены, координата заменена badge;
- bomb: имя цели, урон и сообщение установки сохранены, слово «клетку» перед badge удалено;
- push_result: сообщение о состоявшемся перемещении сохранено, координата заменена badge.

Названия действий в затронутых ветвях телепортации/бомбы экранируются перед включением в HTML; для костра экранирование уже существовало. Оттеснение использует прежний фиксированный текст. Компоновка InfoPanel, JS, CSS, ошибки сервера и standalone_text не изменены. HTML и координаты наблюдателя не записываются в GameState/события/БД. Для системной (3,2) host видит зелёное `# [I:2]`, player — красное `# [I:4]`.

## Регрессии

Новые tools/test_cell_marker_cancel.php проверяют публичный Engine::apply(), включая URL реальной кнопки: host/player, чужую/повторную отмену, удаление pending, увеличение версии ровно на 1, неизменность всей карты, отсутствие маркера и strike после отмены, повторное открытие и выбор с исходными системными координатами, невозможность отменить уже выполненный эффект. Также проверены mandatory forced_strike, его пересечение с cell-marker pending и более ранний обязательный chooser AfterStrikeExecuteChoice.

Новые tools/test_battle_result_coordinates_ui.php проверяют все 30 клеток для обоих viewer и каждое из четырёх сообщений (240 рендеров корректных результатов), цвета относительно половины поля, римские ряды, исходные смысловые части сообщений, разные координаты в одном блоке, сообщения без координат, отсутствующие/некорректные значения, XSS-символы в названиях и неизменность сериализованного состояния до/после View. Отдельно проверено точное сохранение прежнего Coords::render().

Все 17 PHP-сценариев прошли:

- test_cell_marker_cancel, test_battle_result_coordinates_ui, test_battle_coordinates_ui;
- test_battle_defender_ui, test_battle_ally_modifier_ui, test_battle_auto_target_ui, test_battle_death_choice_ui, test_battle_redirect_ui;
- test_charon, test_combat_instant_ui, test_battle_vampire_hp_ui;
- test_whip_cancel, test_forced_directional_movement, test_oyuun_holvert, test_talion, test_kobold, test_storm_caller.

Engine::apply() пишет GameLog, поэтому эти сценарии запускались в отдельной временной копии src/templates/tools. storage реальных партий и БД не использовались. Для новых Engine-фикстур дополнительно используются случайные отрицательные синтетические gameId.

В браузере на 1280 и 390px для обоих viewer проверена настоящая цепочка с публичным Engine::apply(): открытие → переключение стороны и ряда без навигации → нажатие серверной ссылки отмены → pending отсутствует, версия 2, карта открыта, маркеров 0 → повторное открытие → выбор столбца → pending отсутствует, карта закрыта, маркер создан, исходные row/col сохранены, результат содержит `# [I:2]`. Отдельно прошла отмена для обоих viewer при отсутствии загрузки JS-контроллера (29 доступных резервных клеточных кнопок).

Браузер использовал одноразовую сессионную PHP-фикстуру только во временной копии кода: синтетическое состояние и журналы сохранялись там, без изменения настоящей партии. Визуально проверен зелёный badge на мобильной ширине. PHP syntax checks и git diff --check — без ошибок.

## Ограничения и риски

Не проверялись реальная БД, GameRepository::save() и конкурентные HTTP-запросы в живой партии. Браузерная проверка выполнялась через изолированную сессионную фикстуру настоящих View/Engine, без маршрута www/index.php и его PRG. No-JS проверен отсутствием загрузки контроллера; HTML-рендер fallback и отмена через ссылку реально выполнены.

Как и прежде, cancel_pending не содержит ID конкретного pending: устаревший URL может отменить новый допустимый pending того же владельца. Эта семантика команды не менялась. Общий cancelPending обрабатывает несколько pending; существующие ограничения и приоритеты сохранены и покрыты тестами, новая система отмены не вводилась.

Другие контексты координат, текстовые подтверждения, история действий и отображение серверных ошибок остаются вне задачи. Для некорректных координат badge не выводится; достраивать фиктивную клетку или менять сохранённые значения View не пытается.
