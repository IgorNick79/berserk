# Turn Timer T2 — AJAX и InfoPanel

## Контракт и интеграция

Серверное поле `turn_timer` содержит результат существующего
`TurnTimer::snapshot`: period_id, owner, status, remaining_seconds, anchor_at,
pause_reason, server_now и limit_seconds=180. Для старой партии без таймера
передаётся null; загрузка/отрисовка не создаёт период.

- BattleSnapshotRenderer возвращает таймер рядом с ui/fragments. Дополнительный
  необязательный serverNow используется в контролируемых тестах, не приходит из HTTP.
- sendBattleAjaxState включает его в обычный, командный и conflict snapshot.
- battle_sync передаёт актуальную проекцию и при no_change. Для этого не нужны
  новые версии, сохранение games или команды журнала.
- battle_command_status также передаёт таймер из загруженного состояния через
  sendCommandStatus. Unknown outcome без достоверно загруженного состояния не
  получает выдуманных временных данных. Статус команды остаётся независимым.
- InfoPanel включает начальную read-only проекцию для немедленного отображения
  после reload. JS подключается перед battle-sync и не отправляет запросов сам.

TurnTimer, GameState, TurnProcessor, Engine, GameRepository и Command Journal
не изменялись. Сохраняемый формат T1 и лимит 180 секунд прежние.

## Клиент и интерфейс

`battle-turn-timer.js` — только отображение и звуковое уведомление. Между
серверными ответами остаток считается через performance.now(), округляется
вверх до секунды и ограничивается нулём. paused фиксирует остаток, expired
показывает 00:00. Клиент не делает игровой команды при нуле и не меняет серверный
status локально. При офлайне возможен 00:00 до следующего серверного подтверждения.

Контроллер принимает снимки с учётом persistence version, period_id и server_now.
Устаревший период/версия/секунда игнорируются. Дубликат того же серверного отсчёта
не переустанавливает локальную привязку и не возвращает потраченное время.
После AJAX-замены InfoPanel узел находится заново. Контроллер один на root;
интервал отрисовки один, 250 мс, без повторной записи неизменившегося текста.
В скрытой вкладке этот интервал выключается, при возврате используется прошедшее
монотонное время и существующий AJAX-ответ корректирует показания.

Верхняя часть InfoPanel: короткое «#N · Ваш ход / Ход соперника» и фаза ниже.
Подчёркивание заголовка и разделительная линия шапки убраны. Справа MM:SS,
подпись «Ваше время / Соперник», «Пауза» или «Истекло»; состояние различается
также цветом. Принадлежность берётся из timer.owner, не из раннего battle.active.
Новых игровых кнопок и настроек лимита нет.

## Сигнал нового хода

По согласованному выбору добавлен мягкий двухтональный Web Audio сигнал длиной
около 0,27 секунды. Звук включается после первого pointerdown/keydown на странице
и срабатывает один раз при серверном running нового собственного периода.
Первый снимок/reload, повтор polling, стартовая пауза и истечение времени не звучат.
Если браузер блокирует звук или страница ещё не получила пользовательский жест,
это никак не влияет на команды и синхронизацию.

Для будущей замены можно положить `www/assets/sound/turn.mp3` либо `turn.ogg`:
сервер подключит имеющийся файл (mp3 имеет приоритет), иначе используется синтез.
Несуществующий файл не запрашивается.

Открытая вкладка сохраняет прежний polling 2 секунды. Для сигнала в фоне тот же
battle_sync продолжает работать раз в 10 секунд вместо полного отключения.
Это единственное расширение фоновой активности, необходимое для привлечения
внимания к новому ходу. Другой sync-механизм не создан. Во время неопределённой
команды сохраняются прежние блокировка и recovery; звук не разрешает повтор.

## Ограничения T2

- Автоматическое завершение хода, закрытие pending, автоматические паузы по
  владельцу pending и таймер сражения не реализованы.
- Серверная точность — целые секунды T1. Между клиентами возможна разница на
  округление и сетевую задержку; новые ответы корректируют локальный отсчёт.
- Фоновые вкладки/браузер/ОС могут задерживать polling или блокировать аудио.
  Сигнал — best effort, не гарантированная системная нотификация.
- Истечение при чтении остаётся read-only проекцией. T3 должен безопасно завершать
  ход с проверкой period_id и текущего lifecycle, через существующие CAS/Journal.

## Проверка пограничных случаев синхронизации

Версия persistence и server_now проверяются независимо: более старая временная
проекция одного периода отклоняется даже при росте версии. Одинаковая проекция
не сбрасывает локальную монотонную привязку. Смена периода и подтверждённые
pause/resume в одну серверную секунду поддерживаются.

После возврата вкладки в sending клиент сразу проверяет журнал без повторного
POST. Поздний ответ исходного POST обрабатывается также в recovering, включая
подтверждённый отказ до регистрации. Для recovering и syncing сохраняются
проверки поколений отменённых GET. Регрессионные тесты включены в
test_turn_timer_client.js и test_turn_timer_sync.php.

При откате серверных часов старые проекции того же периода, включая новую
паузу, ждут ответа с не более старой временной отметкой. Новый период
принимается сразу. Journal, CAS и правила боя не изменены; T3 не реализован.
