## Безопасное применение миграции после развёртывания

Из корня выбранного checkout запустить `php tools/migrations/20261115_instant_battle_types.php` без --apply. Проверить конфигурацию подключения, SELECT DATABASE(), @@hostname, @@port и ENGINE таблицы cards. Сохранить исходные ukid/name/prop пяти карт в отдельный защищённый backup вне Git; убедиться, что preview меняет только battle_types.

Только после подтверждения целевой БД и отдельного разрешения для production выполнить `php tools/migrations/20261115_instant_battle_types.php --apply`. Затем повторить preview и SELECT пяти prop, сравнить остальные поля с backup. Повторное применение идемпотентно. Не перезаписывать таблицу cards и не импортировать тестовый dump. При несовпадении определения, дубликатах ukid или отсутствии InnoDB миграция должна остановиться, а не обходить проверку.

При откате восстанавливать только согласованные пять prop из backup, с проверкой отсутствия последующих карточных изменений; не восстанавливать всю рабочую БД из тестового стенда.

Итоговый commit hash и подтверждение удалённой ветки выдаются в финальном сообщении после git push / ls-remote. Блокирующих новых дефектов по проведённым проверкам нет; перечисленные независимые UI-assertions и граница вложенности остаются ограничениями приёмки.
