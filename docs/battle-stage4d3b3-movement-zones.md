Ветка `codex/battle-journal-stage4d3`, база `f7454d2`. Незакоммиченные B.1/B.2 сохранены. Production, commit, merge и push не выполнялись.

## Общие точки и порядок

Аудит фактических присваиваний координат и зон показал:

- `MovementEffectResolver::apply/applyForcedPositionChange` вызываются после смены координат и перед последствиями. Через них идут обычное движение, `executeJump`, triggered jump, принудительное движение, отталкивание, телепортация цели, телепортация через врата, перемещение при пикировании, RangedNeighborTeleport и следование симбиота. Проверки клеток в `BattleHelper`, `MovementResolver` и клон позиции в `FirstStrikeJump` не исполняют эти методы и не журналируются.
- Старый `Recorder::moved` находился после movement effects. Теперь текстовый факт записывается в начале общего обработчика эффектов, когда координаты уже изменены. Порядок исполнения эффектов не менялся. Старый вызов `moved` остаётся на прежней границе snapshot; новое поле `text_recorded` подавляет его дублирующий текст. Старые записи без этого поля отображаются по-прежнему.
- `ZoneManager::toField/toFlying` вызываются также при подготовке и до полного reset возвращаемой карты. Поэтому автоматическая запись каждого вызова не добавлялась. Призыв наблюдается в `summonFromDeck` после завершённого перехода; возвращение — после reset в native processors; изгнание — после завершённого `toExile`, только при смене зоны и в battle/game_over. `toGraveyard` не создаёт дополнительную смерть.
- Реальные трансформации меняют `type`, а не UKID: Искатель тайн, получение полёта, полёт по эффекту смерти и приземление Кондора. Они наблюдаются после изменения формы/зоны. Инкарнация в летающую форму описывается возвращением в зону летающих. Перемещение слотов летающих, перемешивание колоды, подготовительная рассадка и примерка координат не превращены в события.

## События и видимость

Добавлены:

| Тип | Содержание |
|---|---|
| `movement.completed` | Карта, фактические `from/to`, механический `movement_type`, отображаемый вид и origin |
| `zone.changed` | Карта, исходная/конечная зоны, конечная клетка, безопасная причина summon/revive/incarnation при наличии |
| `card.transformed` | Карта, известная конкретному участнику исходная форма и конечные type/zone |

У прыжков с дальностью телепортации отображение соответствует принятой в `MovementEffectResolver::applyTeleportAdjacentBonus` классификации (`range >= 10`); игровой `movement_type` остаётся исходным. Общие forced contexts сохраняют своё настоящее обозначение, без угадывания скрытого источника.

Отображаемое имя фиксируется существующим Recorder при записи. События ссылаются на перемещаемую/возвращаемую карту, а не на источник способности: скрытый источник не подавляет публичный результат и не попадает в дополнительные JSON-поля. Неизвестная карта не выдаёт противнику движение или форму.

Перед трансформацией отдельно снимается известность формы для public/host/player. После изменения видимости новая форма может быть известна, а старая останется `null`. В пользовательской проекции нет общего `_before_forms` с данными другого участника. Повторное исполнение без смены type/zone не создаёт вымышленной второй трансформации.

Координаты форматирует существующий `BattlefieldPosition::label`, с зеркалированием для стороны. Состояние и сохранённые координаты не меняются.

## Покрытие до / после

| Механика | До B.3 | После B.3 |
|---|---|---|
| Обычное движение | Текст после movement effects | Один текстовый факт до последствий; прежняя граница snapshot |
| Прыжки семи указанных карт | Не было отдельного содержательного перемещения | Фактические клетки, прыжок/телепортация; отклонённый прыжок не записывается |
| Triggered jump / forced movement | Пропуск | Общая точка, без оплаты действия со стороны Recorder |
| Телепортация цели / врата / соседний телепорт | Пропуск | Фактическая позиция из native context; без раскрытия источника |
| Отталкивание / цель пикирования | Пропуск | Единственная запись общего forced context |
| Шакси | Кубик и раны из B.2/B.1 | Перемещение перед кубиком и последствиями выбора |
| Призыв из колоды | Пропуск | Один завершённый призыв, обеим сторонам после reveal |
| Возрождение наземного / летающего существа | Пропуск | Возвращение после reset HP, зоны и видимости |
| Сшивание плоти | Только последствия здоровья | Отдельное изгнание платы и возвращение существа, без повторной смерти |
| Инкарнация, включая Червя | Только последствия | Возвращение после собственного reset, до союзных/вложенных эффектов |
| Получение полёта / Искатель / Кондор | Нет завершённой формы | Фактическая трансформация; без дублирующего перехода зоны |
| Обычная смерть | Общий `combat.death` | Сохранена одна смерть, технического zone-сообщения нет |
| Изгнание, включая смерть инкарнировавшей карты | Неполно | Смысловое изгнание; смерть и изгнание различаются |
| Колода/рука/отряд при подготовке, reorder, слоты | Не журналировались | Остались вне текстового журнала |

В текущем движке нет исполняемых боевых вызовов `toHand/toDeck/toSideboard/toSquad`: это общие вспомогательные методы. Фиктивное покрытие неиспользуемых игровых механик не добавлялось.

## Примеры

Фактический текст host-проекции парных сценариев (форматтер координат проекта):

```text
Грызь прыгает: Свой [1:3] → Вражеский [1:4].
Демон зависти телепортируется: Свой [1:3] → Вражеский [1:4].
Отряд карателей призывается: поле (Вражеский [1:4]).
Кочевник возвращается с кладбища: поле (Вражеский [1:4]).
Искатель тайн: трансформация — существо → летающее существо.
Тролль изгоняется.
```

При скрытом Грызе его прыжок есть только у владельца. При скрытом Варлоке известный противнику Тролль всё равно получает строку телепортации; ID/имя Варлока в событие движения не включены. Точные координаты, amount и тексты реальных прогонов находятся в файлах доказательств.

## Ограничения и отдельные замечания

- Источники/названия причин не угадываются из `parentId`: это identity ActionResolution, а не обязательно ID карты. Где native movement context не передаёт безопасное имя способности, используется фактический тип перемещения. Расширять содержание эффектов/статусов этим блоком не стали.
- Изменения HP, маркеров и бонусов на клетках остаются собственными эффектами. Не заявляется покрытие всех статусов: B.4 не начат. Само прохождение клетки и сохранение порядка её последствий проверены.
- Диагностические gaps и сертификация Replay Steps не ослаблялись; новые текстовые факты не зависят от сертификации snapshot. Старые матчи не переписывались.
- Прямой повтор `ProphecyProcessor::transformSeeker` в прежнем движке повторно добавляет модификатор, хотя форма уже fly. Это поведение воспроизведено без изменения механики; Recorder не выдаёт его за новую смену формы. Разрешённость повторной команды требует отдельного игрового review, не побочного исправления.
- Существующее предупреждение AJAX `player_settings`, описанное в отчёте B.2, не относится к этому патчу и не исправлялось.
- Полноценная ручная приёмка живыми игроками не проводилась; браузерные проверки автоматические. Production не использовался.

После этого блока работа остановлена. Commit, merge, push, deployment и Stage B.4 требуют отдельного поручения.
