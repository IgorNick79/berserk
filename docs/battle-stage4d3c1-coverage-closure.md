## Исправленные реальные пропуски

1. GraveRitual: переход deck → graveyard не был смертью и не имел смыслового hook. Добавлен `zone.changed` после перехода.
2. Бонус класса ритуала хранится в battle, не в modifiers карт. Добавлен `rule.class_bonus` после установки и после снятия в конце хода. Не пересчитываются характеристики всех существ и не создаются дубли при приходе нового Демона.
3. IncarnationTokenProcessor::grant на кладбище обходил ledger карт поля. Добавлен один `marker.changed` непосредственно после фактического получения жетона.
4. Engine::applyStrikeEffects: прямое закрытие и промежуточные маркеры могли пропускаться/откладываться до конца команды. Необязательный observer-контекст передан из трёх существующих точек вызова; фактические close/marker результаты фиксируются после изменения. Список эффектов, RNG и порядок механики не изменены.
5. StrikeResolver::chooseCloseOrDamage: выбрано закрытие — записывается фактическое изменение, а не технический выбор.
6. DegascaProcessor: изучение новой способности отсутствовало в ledger. `capability.learned` только владельцу, без ukid карты колоды или содержимого способности в JSON противника.
7. CardHealing: реакция Очи могла записываться раньше вызвавшего её восстановления. Observer восстановления перенесён перед ActionResolution reaction; игровой вызов ActionResolution и сами вычисления не перенесены. Теперь лечение → открытие.
8. Риск-аудит общего маршрута выявил прямое открытие Повелителя мёртвых (`s1_147`) при инкарнации союзника: добавлен `status.changed` только при реальном открытии.
10. Риск-аудит инкарнации: обычный жетон начала хода также увеличивается напрямую в TurnProcessor, отдельно от grant. Добавлены фактический marker.changed и incarnation.ready; технический сброс счётчика не изображается отдельным действием.
9. В combat.wounds добавлено фактически применённое `cell_bonus` Света фонаря. Оно объясняет увеличение ран без отдельного дублирующего wound-события и без source_id скрытого источника.

## Command Journal, rollback и HTTP

`closure_transaction_probe.php` повторяет целые интеграционные цепочки под настоящим GameRepository::executeLockedCommand. Для каждой цепочки SQL CHECK временно запрещает события именно её journal_id: проверяется полный rollback games.json/version и числа событий, затем успешный commit, чтение сохранённых host/player/public проекций и committed retry. Ограничение устанавливает только root disposable schema; runtime-пользователь без DDL. Дополнительный режим branches выполняет все 42 адресных сценария тем же locked transaction путём в отдельной synthetic партии. Это SQL интеграция целой цепочки как одной lab-команды, а не утверждение, что каждое вложенное действие выполнено отдельным HTTP-запросом. Отдельные многошаговые HTTP-команды, версии, повтор, cursor и reconnect проверяет общий harness.

Harness сохраняет реальные userId участников fixture-матча; синтетические actor IDs сценариев не подменяют авторизацию. Увеличен лишь защитный лимит числа страниц теста (история стала длиннее 200 страниц по 2 записи), с дополнительной строгой проверкой продвижения cursor при has_more. API и UI не изменены.

Начальные ошибки SQL-проверки были ошибками harness: неполный набор полей для переиспользуемого verifier и потеря synthetic account metadata при установке fixture. Они не исправлялись в рабочей авторизации. Fixture-builder сложных сценариев теперь также берёт реальный type определения: летающие карты создаются в flying, без вымышленных полевых координат. Парные цепочки повторены после этой проверки. Старые Oyuun/Holvert и SwampQueen tests падали на устаревших ACK также на исходном main (baseline outputs сохранены); в тестах используются актуальные ack_id/owner.

- Сертификация Replay Steps не ослаблена; recording_gap остаются диагностикой и не подавляют смысловые события. Исторические записи не переписываются.

- Test fixtures/evidence намеренно содержатся в пакете. Локальные конфигурации и disposable datadir не добавлены. Перед коммитом нужен отдельный просмотр набора добавляемых файлов.
