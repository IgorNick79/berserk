# Королева топи — итог реализации

Изменения подготовлены в king-priest-ui-main поверх 60e7003. Commit/push не выполнялись. Рабочая БД, SQL-схема, Recorder и InfoPanel не изменены. Карта в рабочем каталоге автоматически не обновлялась.

## Точный предлагаемый prop

```json
{
  "zom": true,
  "opponent_turn_end": [
    { "type": "deck_summon", "element": "swamps", "max_price": 5, "own_neighbors": 8 }
  ],
  "actions": [
    { "key": "prophecy_wounds", "name": "Пророчество 1", "type": "impact", "effect": "prophecy_wounds", "count": 1 }
  ]
}
```

`zom` работает штатно; `opponent_turn_end` и `actions` являются уникальными особенностями и читаются через effectiveProp.

## Призыв

TurnPhaseProcessor ставит задачу в штатную очередь конца хода противника, только если одновременно есть подходящая карта в своей колоде и свободная допустимая клетка. Закрытая Королева сохраняет пассивную способность. Собственный конец хода её не запускает.

SwampQueenProcessor перебирает все клетки поля. Соседство — восемь прилегающих направлений; считаются собственные живые экземпляры существ на поле, включая несколько экземпляров на одной клетке. Число не ограничено восемью. Летающая зона, чужие, гибнущие карты и не-существа не считаются соседями. Занятые клетки и блокирующие маркеры исключены. Фильтр колоды использует element=swamps, тип creature/fly и фактическую цену <=5; UKID не хардкодятся.

Pending `pending_swamp_queen_summon` хранит owner, source_id, effect_index, stage, candidate_ids, cells, card_id, cell и deck_viewed. Сначала выбирается карта, затем клетка. Единственный вариант выбирается автоматически, неоднозначные варианты обязательны, отмены нет. Повторные экземпляры показаны отдельно с идентификатором. Выбор использует штатные Panel/PanelSpec/Form, новый общий DeckCardChoice переиспользован и Дегаской. Координаты клетки выводятся штатным Coords с учётом стороны.

Перед выполнением повторно проверяются источник, эффективная способность, карта и клетка. Потеря доступности завершает pending безопасно; оставшиеся допустимые варианты обновляются. Переносится тот же экземпляр из deck, без копирования. ZoneManager.summonFromDeck выделен из существующего появления через пророчество и сохраняет его контракт: полные HP/движение, закрытое и раскрытое существо. Продолжение конца хода — штатный TurnPhaseProcessor.resume.

После завершения просмотренной операции колода перемешивается ровно один раз, в том числе при безопасном завершении без призыва. Алгоритм Дегаски вынесен в ZoneManager.shuffleDeck и используется обоими маршрутами. Промежуточные выборы не перемешивают колоду; повтор завершённой команды не вызывает повторный призыв.

## Пророчество и раны

ActionResolver сначала проверяет исходную выбранную цель штатным маршрутом. Затем используется ProphecyProcessor.peek/commit, Королева закрывается и открывается Пророчество 1. Сравнение использует реальные `cards.name`, не UKID; имя, результат сравнения и количество ран фиксируются при открытии, до дополнительных действий пророчества. Учтены поле и летающая зона обоих владельцев; другие зоны исключены.

Уточнение Project Lead: вызванный из этого пророчества «Отряд карателей» не обеспечивает совпадение сам с собой. Если другой такой отряд уже есть — 2 раны; если нет — 1. Оба случая проверены через штатный вызов, reload и завершение просмотра.

В pending_prophecy.swamp_queen сохраняются source_id, target_id, action_key, revealed_name, name_match, value, applied. Эти данные переносятся при всех штатных пересборках pending: Махинатор и действия вызова открытой карты. Цель не выбирается повторно. После штатного close данные переходят в prophecy_result; источник, цель и доступность эффективной способности повторно проверяются. Выход источника/цели и подавление не позволяют нанести неразрешённые раны.

Нанесение идёт через Engine.applyDamage/DamageResolver с отдельным типом prophecy_wounds, игнорирующим броню в существующем списке прямых ран. Броска кубика и удара нет. Для результата используется существующий impact-экран; InfoPanel не менялся. Pending удалён до завершения эффекта, транзакция защищает от частичного сохранения; retry не наносит раны повторно.

Точечная совместимость ProphecyProcessor: исправлено обращение к неопределённой переменной `$state` при проверке блокирующего маркера в штатном startSummon на `$this->state`. Правила вызова не менялись.

## LuckTest: deck

Новый необязательный массив `deck` использует `{owner, ukid}`. Координаты для deck не допускаются. Старые cards-only сценарии проходят прежние проверки без изменения поведения. Карты загружаются как полные снимки из каталога через существующий генератор резерва; заданные deck-экземпляры занимают часть обычных 30-K слотов, остальные заполняются штатно. Это гарантированные карты резерва, а не замена размера колоды. Повторные одинаковые UKID связываются с разными instanceId.

Публичный JSON сохраняется через LuckTestScenario.root: технический внутренний zone не попадает в формат. Обновлены две точки сериализации RoomSetup и существующее значение textarea SettingsScreen, чтобы deck не терялся после roundtrip. Новый интерфейс настроек не добавлялся. GameState и правила сохранения не менялись.

## Ограничения и готовность

Изолированный сохранённый SQL-каталог не содержит столбца name. Поэтому SQL-тесты использовали явную фикстуру канонических имён через внедрённый lookup Engine. Производственный SELECT ukid,name согласован с существующими обращениями проекта, но не проверен на полном реальном SQL-каталоге. Обновление production prop и проверка настоящих названий/свойств на полном каталоге оставлены Project Lead.

Число >8 соседей проверено модельными несколькими экземплярами на клетке; полноценные будущие правила симбиотов этим не вводятся. Имя берётся из канонического каталога, динамическое переименование карт новая механика не добавляет.

Код готов к практическому тестированию после решения Project Lead и применения предложенного prop к s1_130 уполномоченным способом. Автоматического изменения БД нет. До утверждения не выполняются merge, commit или push.
