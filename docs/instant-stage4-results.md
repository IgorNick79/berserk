# Stage 4 — единый интерфейс и позднее окно Отшельницы

Stage 4 реализован, следующий этап не начат. Предварительный аудит:
[instant-stage4-audit.md](instant-stage4-audit.md).

## Интерфейс

Постоянный блок «Инстант» находится в InfoPanel.renderFooter непосредственно
перед «Завершить ход». Рамка и одна основная кнопка; position:fixed не применяется.
Просмотр карты и переключение содержания больше не скрывают footer.

Штатные карточки выбора способности открываются через details в этом блоке.
Это локальное раскрытие списка: оно не отправляет боевую команду, не меняет
приоритет и не создаёт стек. Сам выбор использует прежние play_turn_instant,
combat_instant_play и choose_defender_option. Выбор цели, количество ран,
результаты и обязательные подтверждения остаются в основном содержимом.

Старый open_turn_instants из scroll-content, автоматические списки запуска из
боевой панели и TurnInstantStackChoice, а также радио-варианты Мага из панели
защитника удалены. Последние перенесены в тот же общий список с прежним source/target.
Пас перенесён в footer без дубликата; нужный пас остаётся даже при отсутствии
последней доступной способности. Для пустого собственного резервного стека
доступен прежний decline_instant_priority («Отказаться»).

## Схема единственной основной кнопки

Решение целиком серверное, InstantControl.project. Клиент не вычисляет цену,
лимиты или доступность и не хранит отдельную игровую истину.

| Состояние зрителя | Основная кнопка | Действие / дополнительные обязательные действия |
|---|---|---|
| Матч завершён / пауза | Блок скрыт | Прежний интерфейс завершения/паузы |
| Ожидающий собственный резерв, нет доступного штатного окна | Отменить резерв | cancel_instant_reservation с request_id |
| Активная сторона, обычный допустимый ход | Сыграть | Прежний open_turn_instants, без изменения допуска сервера |
| Пассивная сторона, обычный ход | Резерв | reserve_instant; стоимость −1, остаток remaining/limit |
| Подключённый внешний обязательный выбор | Резерв | Бесплатно; period_id и origin_choice_id из Stage 3B |
| Штатный turn-стек вне сражения | Сыграть | Раскрыть собственные доступные способности; пас / допустимый отказ |
| Штатные before/after, dice/main/wounds или специальное окно Мага | Инстант | Только существующие боевые права и собственные доступные варианты |
| Открытый стек, собственный приоритет, способностей больше нет | Основная кнопка неактивна | Пас сохраняется |
| Не собственный приоритет | Неактивная кнопка либо блок скрыт | Чужие варианты способностей не передаются |
| Незавершённый picker/внутреннее разрешение | Новый выбор/пас не предлагается | Сначала завершить прежнее обязательное действие |
| Нет подходящих способностей и обязательного управления | Блок скрыт | Наличие instants в prop само по себе ничего не показывает |

В сражении UI не предлагает новую регистрацию резерва, не показывает −1/Бесплатно
и не меняет лимит. Ранее зарегистрированный запрос Stage 2/3B не переписывается:
его можно отменить. Если одновременно имеется штатное боевое окно, основной
кнопкой остаётся «Инстант», а отмена прежнего запроса — вспомогательное действие
в том же блоке, наряду с пасом. Она не должна подменять боевой выбор или пас.
Серверная модель Stage 2–3B и обработка уже принятых запросов сохранены.

Серверная проекция instant_reservation используется для платности, лимита,
запроса и отмены. Рядом добавлена viewer-only instant_control: visible, label,
enabled, command/payload, options, pass/decline/cancel, combat, phase, stack_open,
cost/quota. Она возвращается во всех snapshot/no_change/status/recovery путях.
options содержит только допустимые собственные способности при своём праве
объявления, без полного prop, вражеских способностей или скрытых целей.
Право управляющего действия сверяется с фактическим BattleWaitResolver, поэтому
родительский стек не обходит незавершённый выбор цели или wounds-resolution.

Существующий AJAX заменяет серверный HTML блока после изменений; F5 восстанавливает
его из сохранённого состояния. Версии battle-ui.js в battle/game_over обновлены,
CSS уже использует существующий hash ключ. Новый клиентский игровой автомат не нужен.

## Отшельница

prop и effect redistribute_wounds не менялись. Новые объявления wounds исключены
из dice/main и общего раннего окна без фазы. После финального result ACK:

1. Подтверждено damage_applied; dice-result сюда не попадает.
2. При наличии живого потенциального wounds-источника выполняется штатный
   finalizeDying, погибшие уходят на кладбище. Без такого источника прежний
   порядок смерти/последующих эффектов остальных боёв не меняется. Это проверка
   наличия точки lifecycle, а не разрешение способности по raw prop: после
   обработки смерти реальная доступность заново проверяется через getInstants.
3. Одноразовый wounds_window_done предотвращает повторное открытие.
4. Если есть доступная способность и реальные допустимые раны, openWindow открывает
   тот же combat-стек, с combat_instant_window=wounds.
5. Декларации, LIFO и последовательные пасы используют прежние команды.
6. Объявленные записи разрешаются только через существующую wounds-фазу и
   WoundTransferProcessor. Затем продолжается прежний after-result путь боя.

Чистая canRedistributeCombatWounds использует тот же collectDonors: живой союзник
на поле/во фланге, исключая источник, с damage_taken_this_strike и фактическим
дефицитом HP; есть живой допустимый получатель, отличный от донора. Источник
проверяется общими getSourceInstants/getInstants Stage 3A: живой, раскрытый,
незанятый, допустимая зона, поворот, условия, ресурсы, лимиты, effectiveProp.
Погибшие/умирающие существа донорами и получателями не являются.

Ни start/chooseSource/chooseAmount/chooseTarget/chooseTargetAmount/finish, ни
сам эффект перераспределения не переписаны. Проверено сохранение суммарного HP:
две раны уходят с донора и появляются у получателя. Это не обычное лечение.
Пустое окно пропускается. Пасы по пустому wounds-стеку и завершение непустого
возвращаются к continueAfterStrikeResultAck, а не к apply/recalc предыдущих фаз.
После завершения матча у финализированного боя закрывается прежний combat lifecycle.

Сохранённые до Stage 4 уже объявленные pending_wounds_resolution продолжают
разрешаться прежним способом; дополнительное новое окно после них не создаётся.
У вложенного боя собственный wounds_window_done и прежние CombatContinuation
frames. Вложенный forced strike с Отшельницей и последующее восстановление
родительского бесплатного turn-стека проверены.

отдельного запуска. Обе ориентации host/player: полезные/отсутствующие/смертельные
раны; закрытый, погибший, скрытый, подавленный источник; ресурсы/лимит; несколько
