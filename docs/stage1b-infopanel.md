## InfoPanel и приоритеты

Единственный внешний InfoPanel остаётся контейнером info_panel_html и является вертикальным Flexbox. Header использует прежний renderStatusHeader(): номер хода, активная сторона и фаза вычисляются из тех же серверных данных. Content имеет flex:1, min-height:0, overflow-y:auto. Footer не сжимается и расположен вне Content.

Существующий buildPanel не переписывался. Изображение, имя, характеристики, способности, режимы, ссылки и формы передаются в новый контейнер battle-selected-card внутри Content. Старой battle-panel-side в DOM больше нет; её 320 px и промежуток 12 px переданы левой игровой области.

Порядок renderBody сохранён: активный Choice, затем pending_prophecy, strike (включая результаты), pending_dive, обычные сообщения/инстанты. Текущий контекст стоит первым, выбранная карта — ниже, поэтому обычный просмотр карты не заменяет обязательное действие. При отсутствии выбора контейнер карты пуст и скрывается CSS. Устаревший порядок игровых приоритетов не переопределялся.

В Footer всегда видны два элемента. end_turn — прежняя ссылка только для активного игрока в незавершённом бою без Choice/strike/показываемых legacy-pending и без обязательной атаки. Для обязательной атаки используется существующий CardStats::getForcedStrikeTarget. В остальных случаях отображается disabled button. Это отображение ограничений существующих Engine/TurnProcessor; сервер продолжает принимать окончательное решение.

resign — прежняя ссылка с прежним подтверждением у обоих игроков во всех незавершённых боевых контекстах. Исправление 2d48026 позволяет её выполнить независимо от pending. Команды end_turn/resign удалены из прокручиваемого renderBody, поэтому дублей нет.

## Debug и AJAX

Существующий buildDebug не менялся. Единственный debug-panel расположен в скрытом aside, занимающем всю доступную высоту левой части оболочки. Overlay абсолютно позиционирован, не участвует в Grid и имеет собственную прокрутку. Бургер синхронизирует aria-controls/aria-expanded, повторное нажатие и Escape закрывают панель. Escape возвращает фокус на бургер. Если сервер не сформировал debug, бургер disabled, диагностические данные не выдумываются.

Debug обновляется внутри уже существующего info_panel_html, нового поля ответа не добавлено. Набор шести AJAX-фрагментов сохранён. Полная страница и AJAX-снимок содержат тот же HTML выбранной карты; клиент перед применением снимка составляет info_panel_html и panel_html в отсоединённом template. Затем заменяет родителя один раз и не пишет в старый дочерний DOM-узел. Наличие целей проверяется до изменений. Проверки sync_version, uiRevision, последовательностей запросов и журнал команд сохранены.

Контроллер debug использует один делегированный click-handler и один Escape-handler. MutationObserver обновляет доступность и сохраняет открытый overlay после замены фрагмента. Повторная загрузка battle-ui.js не регистрирует обработчики второй раз; единственное локальное состояние — открыт ли debug.

- Крондак: открытие pending, сторона/ряд, отмена, повторное открытие, выбор клетки, появление костра и закрытие источника. Header/Footer видны, завершение хода заблокировано.

- Сдача пассивного host во время pending player: игра перешла в game_over, winner=player, pending не выполнился. В БД сохранились прежние карты, маркеры не появились.
- Журнал подтвердил ровно ожидаемые команды: у партии 14 action×2, cancel_pending×1, choose_cell_marker×1, confirm_strike×2, end_turn×1; у партии 15 action×1 и resign×1. Дублирующих отправок не было.

Новый браузерный harness прошёл по 14 проверок для обоих viewer: независимое составление вложенных фрагментов, отклонение заведомо старого sync_version с диагностическим HTML, восстановление актуального снимка, отсутствие дублей debug/обработчиков, Escape, геометрия и сохранённые контейнеры. Для проверки составления harness намеренно удаляет HTML карты из родительского фрагмента и оставляет его в panel_html. Повторно загружает battle-ui.js и проверяет работу одного клика. Игровые команды этот harness не отправляет; их результаты проверены отдельно через настоящую БД, как описано выше.

Существующий браузерный набор Крондака прошёл 552 проверки для host и 552 для player, включая независимые замены фрагментов в обоих порядках, старые узлы, несовпадающие снимки и восстановление после ошибок. Без picker-контроллера прошли по две проверки сохранения видимых fallback-ссылок для каждого viewer.

## Найденные проблемы и согласованные ограничения

1. Перенос panel_html под заменяемый info_panel_html делал исходный кеш DOM-контейнеров небезопасным. Исправлено составлением родителя и дочернего фрагмента до замены и поиском актуальных целевых контейнеров.
2. Старый renderBody выводил end_turn/resign только в обычном ходе активного игрока. Теперь постоянный Footer доступен обоим; серверная допустимость команд не менялась.
3. Исходный debug жил внутри scrollport поля и не обновлялся AJAX. Теперь это overlay с актуальными серверными данными в существующем фрагменте.
4. В AJAX-базе legacy GET-команды боя перенаправляются без выполнения. Fallback-ссылки и их параметры сохранены, но выполнение боевых команд без JavaScript этим этапом не восстановлено. Пользователь явно согласовал: «Да, fallback отдельной задачей». Это не регрессия Stage 1B и не скрытое изменение протокола.
5. Настоящий browser zoom во встроенном браузере не подтверждён: Control+Equal не изменил viewport или devicePixelRatio (остался 1). Проверен меньший доступный viewport 1280×560; реальный zoom следует дополнительно проверить вручную.
6. Игнорируемые изображения карт отсутствуют в текущем checkout. Разметка, src, onerror и характеристики сохранены; загрузка реальных иллюстраций не подтверждена. Графика не перерабатывалась.
7. Полный мобильный редизайн не выполнялся, как и требовала задача.

После коммита рабочее дерево чистое. Коммит и точный итоговый SHA указаны в сообщении передачи. Решение передано на code review, окончательное принятие остаётся за Project Lead.
