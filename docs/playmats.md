# Персональные коврики — реализация и проверка

Дата: 20 октября 2026 года. Проект: `C:/Users/mi/Documents/Codex/berserk`.

## Поведение

При `GameRepository::create()` обоим известным участникам независимо назначаются коврики из явного каталога `mat-001`–`mat-018`. ID записывается в `games.json.players.<role>.playmat_id`. При загрузке отсутствующее значение остаётся `null`: старые партии используют `playmat_default.webp`, массового назначения нет. Схема таблиц не меняется.

Каталог отделяет стабильные ID от путей и порядка файлов. `PlaymatCatalog::assign()` — отдельная политика назначения, пригодная для будущей настройки профиля. Она пропускает отсутствующего участника (`userId <= 0`) и сохраняет уже назначенный ID. В текущем проекте оба участника известны при создании; отдельного потока позднего присоединения нет. При появлении такого потока нужно вызвать эту политику при добавлении участника и сохранить партию.

Драфт и просмотр колоды получают фон своего участника через CSS-переменную. Размеры элементов, расположение карт и обработчики прегейма не менялись.

В бою два абсолютных фоновых слоя занимают по половине прежнего `battle-layout`: соперник сверху, текущий игрок снизу. Изображения используют `cover`, не поворачиваются и не перехватывают события. Экватор — линия в 2 px с тенью, позади игровых элементов, без участия в расчёте геометрии. Пагинация летунов не менялась.

Меню «Коврик» открывает две страницы по девять широкоформатных превью. Превью используют исходные файлы с `contain`, поэтому изображения разных пропорций не растягиваются и не обрезаются. Выбор отмечен зелёной рамкой; страница — существующим бронзовым стилем круглых чипов. Закрытие: Escape, кнопка ×, бургер или нажатие снаружи.

## Запись и синхронизация

Отдельный POST `ajax=playmat` проверяет CSRF и принадлежность идентифицированного пользователя игре. Принимает только ID из каталога. Получателя изменения сервер вычисляет по существующей идентификации; `player_id` и `player_key` из payload не используются.

`setPlaymat()` открывает транзакцию, читает свежую строку `FOR UPDATE`, меняет только собственный `playmat_id` и сохраняет JSON с существующим CAS по `games.version`. Боевой движок, автоматические переходы и обработчики таймеров из этого действия не вызываются. Повтор уже выбранного ID не создаёт запись.

Существующая версия JSON защищает от потерянных записей: устаревшая игровая запись получает штатный конфликт, а косметическая запись после игрового действия читает уже обновлённое состояние. Клиент после подтверждения коврика обновляет CAS-курсор только если подтверждённый сервером игровой JSON совпадает с уже отображённым. Если между запросами произошло игровое действие, курсор не перескакивает через него.

Для polling передаётся `render_token`: SHA-256 сериализованного состояния без `playmat_id`. Если игровые данные совпадают, сервер отвечает `no_change` с ковриками, не формируя HTML-фрагменты. Клиент меняет только фоновые CSS-переменные. Любое изменение остального JSON требует обычного snapshot. Фон имеет собственную проверку монотонной версии, поэтому старые ответы не откатывают выбор. Ответ отдельного POST не содержит таймера и не обновляет его.

## Оставшиеся ограничения

- Сохранена существующая схема `?first` / `?second`: она выбирает условного пользователя 1 или 2, не являясь полноценной аутентификацией. Выбрать другую роль этой схемой по-прежнему возможно. Новое действие не расширяет её и не принимает произвольного получателя из payload.
- При действительно одновременной устаревшей игровой команде действует существующий CAS/409; неподтверждённое действие нужно повторить по штатному поведению клиента. Косметика не перезаписывает игровые данные. Обычное действие сразу после подтверждения собственного выбора использует уже обновлённую версию.
- Отдельного позднего присоединения сейчас нет; предусмотрена повторно используемая политика назначения без рандомизации при загрузке старых игр.
- Серверный reconnect и обновление страницы восстанавливают фон из БД. Постоянные сетевые ошибки показывают ошибку сохранения; автоматическая бесконечная отправка косметических запросов не добавлялась.
