## Контракт для разработчиков

- **Одна или несколько карт.** Сначала вычислите разрешённых кандидатов. Передайте строки в `CreatureChoice::confirmed()` и верните `PanelSpec` с исходной формой команды. Явно укажите min/max и тип checkbox, если сервер ждёт массив даже при максимуме 1. Передайте отдельный `instanceId`, если команда принимает другое значение. Адаптер сохраняет порядок отправки при сортировке строк.
- **Подтверждаемый шаг с отменой.** `CreatureChoice::targetPanel()` использует исходные hidden-поля и URL отмены. Когда кандидатов нет, остаётся отдельная кнопка отмены. Отложенные действия по кнопке подтверждения не выводите в виде временных ссылок для последующего разбора.
- **Группы.** Каждая `CardSelectionGroup` объявляет ID, поле, кандидатов и лимиты. Экземпляр в двух группах выбирается только через панель.
- **Немедленная ссылка.** Передайте `instanceId` и готовый URL в `immediateButtons()`. Адаптер меняет подпись, команда остаётся ссылкой.
- **Вне поля.** Установите `field:false`. Одинаковые открытые карты на кладбище различаются существующим номером экземпляра.
- **Идентичность.** Используйте токен решения и шаг. CombatPick и StitchRevival используют уже существующие токены. Для InstantPick, Hydra, обычного Revive, Talion и Intrigue отдельного стабильного токена в исследованном Pending нет. Консервативная версия может сбросить выбор при изменении состояния. Перенос между разными активациями по одному `pendingKey()` не используется. Устранение сбросов при смене версии потребует добавить идентичность при открытии Pending отдельной задачей.

## Аколит, Рагнар, Анубисар

- Аколит использует одиночный шаг `choose_multi_discharge` с одним элементом в `target_ids[]` для серии, сохранённые последовательные сражения и итог. Защита в серии оставляет все HP прежними, что проверяет `test_ajax_multi_target.php`. Stage 4.2 эту механику и отправку не меняет.
- Собственная Вальхалла Рагнара автоматически готовит безответный удар. Выбор цели бывает у удвоенной Вальхаллы, которой цель нужна по её правилам. Тест Рагнара проходит оба маршрута. Stage 4.2 оставляет немедленные кнопки ValhallaPick и прежнее сообщение о Вальхалле.
- Серверный тест Анубисара прошёл. Практическая проверка на стенде и работа `debug_roll` остаются отдельными вопросами.
