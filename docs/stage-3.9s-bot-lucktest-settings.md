# Stage 3.9S — настройки LuckTest с ботом

В лобби кнопка «Играть с ботом» открывает форму LuckTest. «Начать игру» отправляет настройки на существующий обработчик создания приватной партии. «Отмена» возвращает в лобби. Поддерживается старт сразу в бой. Человек занимает host, бот — player.

| Поле | Значение по умолчанию | Контракт |
| --- | --- | --- |
| Размер отряда | 6 | Целое число 3–10 |
| Целевая стоимость | 45 | Целое число 10–60. Сумма фактической стоимости может отличаться |
| Балансировка летающих и пингеров | Включена | Сопоставляет присутствие этих категорий |
| Балансировка золота и серебра | Включена | Сближает стоимость отрядов по видам кристаллов |
| Автоматическая расстановка | Random | Random или экспериментальный Smart. При заполнении сценария форма выбирает Random, сервер отклоняет конфликт |
| Фора сопернику | Выключена, 0/0 | Золото и серебро от 0 до 5. Применяется к player штатным генератором |
| Обязательные карты | Пусто | JSON со списками cards и deck для аккаунтов с Debug-доступом |

Форма переиспользует поля SettingsScreen, преобразования LobbyWizard, общий блок форы и существующие стили. RoomSetup и GameSettings разбирают параметры. Бюджет хранится в lucktest_total_cost. Для прежних внутренних вызовов без настроек сохранён исходный набор значений.

LobbyStore передаёт проверенный setup через существующую транзакцию в MatchCreator. В этой же транзакции проверяется старт в battle. При ошибке изменения комнаты, партии и журнала откатываются. Повтор с тем же ключом и настройками возвращает ID партии, а изменение параметров при том же ключе даёт 409.

Генератор LuckTest добавляет обязательные карты в указанные зоны и заполняет свободные места. Резерв не входит в бюджет основного отряда. В проверочном матче при выборе четырёх карт обе стороны получили по четыре карты на поле и по 26 в резерве. Тест подтвердил попадание обязательных карт в заданные зоны. На отдельном каталоге с различающимися ценами проверена фактическая стоимость основного отряда.

## Проверки

- Edge проверил значения по умолчанию, отмену, изменение числа карт и бюджета, сценарий обеих сторон, переключение на Random при заполнении сценария, балансировку, фору и повтор запроса. В отдельной партии бот ответил штатной командой. Перезагрузка сохранила ID партии.
- Изолированная MariaDB 10.8/InnoDB проверила настройки и состав, права Debug, права виртуального участника, подменённые значения, отсутствующего бота, параллельный повтор, принудительный rollback и обычные PvP и LuckTest.
- 45 регрессионных наборов и 743 позиционных контроля прошли. Воспроизвелись четыре известные ошибки baseline — test_bulbagur, test_lucktest_manual, test_lucktest_quick и test_stage31_fixes.
- SHA256 постоянного журнала партии 0 совпал с контрольным манифестом Stage 3.9R. 521 остальной отслеживаемый production-файл совпал с HEAD после нормализации переводов строк.

Артефакты проверки находятся в [evidence/stage-3.9s](evidence/stage-3.9s).

## Практическая проверка

1. Войти в лобби на стенде с настроенным аккаунтом бота и нажать «Играть с ботом».
2. Проверить значения 6 и 45. Нажать «Отмена» и убедиться, что комната не появилась.
3. Открыть форму снова. Выбрать, например, 4 карты и 20 кристаллов. При необходимости поменять балансировку и фору.
4. Под аккаунтом с Debug-доступом указать существующие коды карт в JSON из примера формы. Использовать cards для отряда и deck для резерва. Форма переключит расстановку на Random.
5. Нажать «Начать игру». Проверить состав и ответ бота. Перезагрузить страницу и убедиться, что ID партии сохранился.
