# Компактный выбор клетки Крондака

Реализован в `codex/battle-ui-coordinates` поверх `c39bc2f`. Требуется code review и подтверждение Project Lead; задача не считается принятой автоматически.

## Архитектура

Core, CellMarkerChoice, ChoiceRegistry, структура pending, правила и публичные команды не изменены. BattleScreen/InfoPanel по-прежнему получают состояние и полностью формируют HTML на сервере. В изученной ветке нет AJAX-обработчика боевого поля; fetch используется таймером драфта и при изменении состояния перезагружает страницу. Обычные игровые ссылки отправляют GET-команды через www/index.php. Новый контроллер подключён defer-скриптом в battle.tpl, без зависимостей и без реализации AJAX.

CellMarkerPicker::decorate() сохраняет исходные действия, URL и их порядок, включая отмену. Для marker=bonfire добавляет в PanelSpec необязательные данные cellPicker. Группы вычисляются только во View через BattlefieldPosition: own/enemy, числовой игровой ряд 1–3, столбец относительно наблюдателя. JavaScript не преобразует координаты и не вычисляет правила.

Panel выводит скрытый компактный блок и видимые оригинальные кнопки. В компактном блоке есть стороны, ряды I/II/III и только разрешённые ссылки столбцов с исходными системными координатами. Индикаторы поля стали римскими и крупнее (34px); нейтрально-серая шкала столбцов уменьшена до 12px. Внешний размер клеток остаётся 102×102, общая grid-сетка шкалы/строк сохранена. Coords::rowLabel() форматирует только отображение; BattlefieldPosition возвращает прежние числовые значения.

## Временное состояние и синхронизация

Контроллер cell-marker-picker.js хранит только ID снимка, сторону и ряд в замыкании. Один делегированный обработчик click и один MutationObserver ограничивают операции корнями текущего выбора в InfoPanel и поля. Долговременных ссылок на заменяемые узлы нет. Повторная загрузка скрипта проверяет маркер установки и не добавляет обработчики.

Изначальный порядок: свои I, II, III; затем вражеские I, II, III. Выбирается первая непустая группа. При переключении стороны текущий ряд сохраняется, если доступен; иначе выбирается первый доступный ряд этой стороны. Недоступные стороны/ряды отключены, недоступные столбцы отсутствуют. aria-pressed, native button, доступные ссылки, видимый focus и размер минимум 44px обеспечивают клавиатуру и touch.

View помечает только существующие допустимые пустые клетки. JS сопоставляет ключ клетки, готовую группу и исходный URL в обоих фрагментах. Только активная группа подсвечена и имеет видимые ссылки href. У остальных ссылок удалены href, они скрыты и исключены из tab order; делегированный обработчик дополнительно блокирует активацию неактивных целей. Карты и оверлеи не заменяются. В устаревшем списке кандидат, которого нет среди целей поля (например, занятая клетка), не становится активным компактным вариантом. Окончательная валидация всегда остаётся у сервера.

## Независимая замена фрагментов

Оба фрагмента получают одинаковый SHA-256 ID серверного снимка из gameId, version, viewer и pending. Это метаданные View: ID не сохраняется в GameState, pending, БД или URL. При замене любого фрагмента того же снимка сохраняются выбранные сторона/ряд. Если снимки отличаются, компактный интерфейс временно отключается, резервные кнопки доступны, цели поля отключены до получения согласованного второго фрагмента. Новый снимок выбирает начальную группу заново. Изменение version рассматривается консервативно как новый снимок.

Если InfoPanel закрывает pending раньше обновления поля, старые цели поля отключаются. При исчезновении обоих фрагментов временное состояние очищается. MutationObserver поддерживает повторные открытия/закрытия, восстановление после отсутствующего фрагмента и не наблюдает собственные изменения hidden/class/aria, поэтому нет циклической инициализации. Для будущего загрузчика фрагментов отдельный вызов init не требуется, если исходный battle-скрипт уже загружен. Загрузчик, впервые открывающий BattleScreen без полной страницы, должен подключить этот скрипт как часть экрана.

## Progressive enhancement

Серверный HTML содержит полный рабочий список оригинальных действий и отмену. Компактный блок скрыт атрибутом hidden. JS скрывает только резервные клеточные ссылки после успешной проверки и синхронизации обеих частей; отмена и другие действия остаются видимыми. Без скрипта, при неполных контролах, отсутствии/несовпадении фрагментов или ошибке инициализации доступны резервные серверные действия. Их URL сохраняются точно.

## Ограничения и риски

Браузерные проверки используют локальную фикстуру настоящего BattleScreen без БД/живой партии; реальные сетевые AJAX-запросы не проверялись, поскольку их нет в этой ветке. Независимая DOM-замена проверена в фикстуре. No-JS проверен отсутствием загрузки контроллера и доступностью исходного HTML, без отключения всего JavaScript средствами браузера. Некоторые иконки карт не загружаются в тестовом корне репозитория; на геометрию/ссылки это не влияет.

Переход к новому version сбрасывает временный выбранный ряд. Сервер по-прежнему отвечает за отклонение устаревших ссылок, в том числе fallback; скрытие/disabled не является игровой авторизацией. Остальные choosers и настоящий AJAX остаются вне задачи.

## Lifecycle review: дополнительные исправления

Подтверждены риски в предыдущем sync(): видимость отдельных столбцов менялась во время обхода групп, до проверки последующих групп; несовпадающие URL считались просто отсутствующими целями, что допускало частичную активацию несогласованного интерфейса. Кроме того, ошибка оформления клетки во время аварийного отключения могла прервать очистку остальных ссылок. Проверка клика также могла использовать состояние до выполнения MutationObserver при немедленной активации после DOM-замены.

Теперь сначала полностью проверяются контролы, уникальность групп/ключей, контейнеры целей, соответствие групп и точное равенство URL. Несогласованный существующий target отклоняет весь компактный интерфейс; отсутствующая на поле цель по-прежнему может быть скрыта как занятая клетка устаревшего pending. Изменения DOM выполняются после валидации, а временный выбор фиксируется только после успешного применения. Команды/координаты не преобразуются и URL не переписываются контроллером.

Аварийное отключение удаляет href перед изменением оформления каждой клетки и продолжает очистку, если оформление конкретного target бросает исключение. Compact скрывается, оригинальные fallback-ссылки восстанавливаются через HTML-атрибуты. Перед окончательным кликом на поле/столбце снимок дополнительно проверяется синхронно, поэтому устаревший выбор блокируется даже до callback observer.

В браузерные проверки добавлены: поздняя ошибка группы без предварительных изменений видимости столбцов; позднее несовпадение URL при одинаковом ID; постоянная ошибка оформления после активации полевой команды; ошибка после начала скрытия fallback; последовательные pending с одинаковыми клетками, но новыми ID и base URL (game=77/game=88), оба порядка замены фрагментов и немедленные клики до observer; смена стороны при отсутствии прежнего ряда; восстановление корректных фрагментов без повторной регистрации обработчиков. Серверные действия в тесте не выполняются, меняются только тестовые DOM-снимки.

Финально прошли все 16 браузерных прогонов (host/player, 1280/390, sparse/stale/observer/no-controller), девять прежних PHP-сценариев, node --check обоих JS-файлов и git diff --check. Core, CellMarkerChoice, ChoiceRegistry, pending, координаты и команды не изменены. Изменены только www/assets/js/cell-marker-picker.js, tools/test_cell_marker_picker_browser.js и этот отчёт.

Ограничения: тестируется настоящая клиентская логика в локальной браузерной фикстуре, а не живая партия с БД. Сетевой AJAX отсутствует в ветке; вместо него проверяются независимые DOM-замены. Ошибки применения воспроизводятся тестовой инъекцией исключений в DOM setters/оформление. Сервер остаётся окончательным валидатором устаревших действий, включая fallback. Требуется повторный code review и подтверждение Project Lead.
## Review: принадлежность ссылки актуальному DOM-контейнеру

После sync() обработчик повторно находит актуальный field/picker в соответствующих battle-field/info-panel и сравнивает его с closest-контейнером исходного target. Проверяются isConnected и contains; совпадение snapshot ID без совпадения самого DOM-контейнера больше не достаточно. Проверка распространяется и на переключатели старой панели. У актуальных ссылок URL не меняется; fallback без контроллера сохраняется.

Существующий MutationObserver дополнительно удаляет href у полевых/компактных ссылок действительно отсоединённых removedNodes. Это важно, поскольку события полностью отсоединённых деревьев не доходят до document. Переподключённые к документу узлы не очищаются как удалённые, но их клики отклоняются, если они находятся вне актуального контейнера. Новые обработчики на клетки/панели не добавлены, долговременные ссылки на старые узлы не хранятся.

Браузерные регрессии теперь заменяют целевой фрагмент в window capture, когда путь клика уже построен: исходный target оказывается отсоединённым либо возвращается в документ вне актуального контейнера. Проверены оба порядка независимой замены, равные snapshot ID, повторные клики старого узла, отзыв href у удалённых ссылок, приём актуальных ссылок с неизменённым URL и отсутствие новых document-обработчиков.

Все 16 браузерных прогонов прошли (оба viewer, 1280/390, sparse/stale/observer/no-controller), а также девять существующих PHP-сценариев, node --check и git diff --check. Изменены только cell-marker-picker.js, браузерный JS-тест и этот отчёт. Core, pending, BattlefieldPosition и серверная валидация не изменены.

Ограничения: проверяется локальная фикстура без живой партии/БД и сетевого AJAX. Полностью отсоединённые события не проходят через document; отзыв их href выполняется observer до следующей обычной пользовательской задачи. Произвольный сторонний скрипт, вызывающий native click на отсоединённом узле в том же синхронном стеке до callback observer, не контролируется делегированным обработчиком. Подмена/прямое использование сохранённых URL всё равно требует серверной валидации. Требуется повторный code review.
