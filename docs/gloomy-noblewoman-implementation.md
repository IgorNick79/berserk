# Мрачная дворянка (s1_154) — реализация

## Результат

Реализована согласованная граница **карточного излечения до изменения HP**. Начальные характеристики Дворянки — 8/12 HP, постоянные zor и броня 1; вампиризм использует прежний обработчик. Первое карточное излечение учитывается глобально для текущего хода. Дворянка активной стороны проверяется раньше пассивной, независимо от источника излечения. При подтверждённом конфликте double/block результат автоматически равен нулю, без пользовательских pending.

Исходная база — 9fdb6cf, ветка codex/instant-system-stage4. Commit/push, изменение рабочей БД и её схемы не выполнялись. InfoPanel.php и WoundTransferProcessor.php не изменялись. Вампиризм, регенерация и трупоедство не переведены на новый путь. Предыдущий документ gloomy-noblewoman-audit.md оставлен как исторический аудит; его предложение перехватывать восстановление HP заменено согласованной узкой реализацией.

## Полный prop

Файл: `docs/gloomy-noblewoman.prop.json`.

```json
{
  "zor": true,
  "armor": {"value": 1, "permanent": true},
  "vampire": true,
  "hp_max_override": 12,
  "first_card_heal": {"threshold": 8}
}
```

Общие обработчики не содержат привязок к s1_154/s1_81. Prop рабочей карты Project Lead применяет самостоятельно, как указано в задании.

Создание руки и колоды берёт hpMax из уже существующего hp_max_override, сохраняя стартовое hp из health. Поэтому при health=8 экземпляр появляется с hp=8, hpMax=12. В отображении боевой карточки используется актуальный максимум Дворянки. Прежнее отображение бесконечного здоровья других вампиров сохранено.

Собственная постоянная броня помечена явно: сохраняется только armor с полями value/permanent. Это не делает постоянными условные/строевые armor и выданные модификаторы других карт. zor остаётся в прежнем PermanentFeatures; vampire и first_card_heal подавляются обычным effectiveProp.

## Обработка излечения

`CardHealing::begin` принимает источник, цель, числовую величину, происхождение и данные следующего этапа. Это не перехват присваивания HP: вызовы стоят только в явных карточных эффектах.

Подключены:

- active heal, включая Сшивателя; multiheal;
- выбранное излечение Кобольда и излечение Келе после удара;
- излечение защищаемого при выборе Бьерна;
- heal/heal_turn_wounds инстантов;
- излечение Предсмертного дара, Дикого целителя и Шакси;
- явное излечение при гибели, включая выбранную цель;
- heal Вальхаллы и явное карточное heal конца хода.

**Не подключены:** вампиризм, обе реализации регенерации, трупоедство, перераспределение ран, создание/возрождение/призыв, увеличение hpMax, нормализация HP. ActionResolution::healed остаётся уведомлением после результата.

Состояние `battle.card_healing` хранит ключ хода, отметку first_used, идентификаторы операций, события, последний результат и пояснение автоматического конфликта. Начало нового хода сбрасывает ограничение явно. В фазе конца хода учитывается именно заканчивающийся ход: старый движок заранее переключает battle.active/turn, поэтому операция использует контекст turn_phase.phase=end, active_key. Первое излечение конца хода не получает преждевременно новый лимит.

Отметка расходуется при первой принятой попытке даже без доступной Дворянки, при 8 HP, подавлении, полной цели и отказе. Числовая попытка на 0 также учитывается, но не создаёт бессмысленного выбора умножения нуля. В multiheal сохранены исходный ActionResolution ID и последовательность выбранных целей: только первое конкретное излечение может быть модифицировано; весь групповой эффект автоматически не удваивается. Итоговый ActionResolution остаётся одним агрегатом, как прежде.

До восстановления HP сохраняются и проверяются отдельно:

1. declared — назначенная величина;
2. modified — величина после Дворянок;
3. restored — фактически восстановленное здоровье с учётом максимума;
4. wounds — фактическая потеря HP от замены Вожака.

При автоматическом конфликте нет pending ни одной Дворянки и нет нового ACK. Понятное пояснение выводится через PanelSpec в BattleScreen для обоих игроков; оно сохраняется и при дальнейших целях группового излечения. InfoPanel не менялся. Обычные существующие результаты отражают фактическое излечение либо заменяющие раны.

## Pending и continuation

Выбор Дворянки: `pending_card_heal` с owner владельца Дворянки, source_id Дворянки, случайным token и сериализуемой operation. В operation находятся источник/цель излечения, declared/modified, список проверок в порядке активная → пассивная, текущий индекс, принятые решения и return_to.

Команда `choose_card_heal` требует владельца и текущий heal_token. Кнопки — «Применить» / «Отказаться». Проверка живого источника, effectiveProp и порога повторяется при ответе. Ушедшая или подавленная Дворянка не применяет сохранённую возможность. Повторная/устаревшая команда не исполняется второй раз.

После Дворянок при modified>0 проверяется только **сам Вожак-цель**. Переиспользуется `pending_heal_instead_wound`; вложенная card_heal сохраняет операцию, token связывает ответ с текущим выбором. Соседи проверяются заново. Полный HP не препятствует замене; X=modified до ограничения hpMax. modified=0 не открывает замену. Другой Вожак не реагирует на излечение третьей карты.

Применение замены расходует одно использование, отказ не расходует. Лимит до трёх применений сбрасывается на каждом новом ходе обоих игроков; устранён перенос прежнего счётчика Вожака в ход соперника. Подавление/уход Вожака во время ожидания безопасно снимает замену и продолжает обычную часть излечения.

Продолжения — именованные стадии обработчиков action/strike/instant/death/turn/valhalla. Сохраняются данные, а не PHP-объекты, замыкания или стек вызовов. Корневая ActionResolution identity удерживается в ожидающем контексте до завершения. Зависимые стадии гибели возвращаются через сериализуемые followers.

- Оплата и независимый урон Предсмертного дара выполняются один раз до его части излечения.
- Движение Дикого целителя не повторяется после выбора.
- При возобновлении удара продолжается стадия после уже выполненного повреждения/излечения; кости повторно не бросаются.
- При возобновлении стека инстантов завершается сохранённый текущий элемент, его эффект заново не применяется. Нижние элементы ждут завершения выбора.
- Вальхалла и конец хода сохраняют оставшиеся эффекты; например, последующий жетон не выдаётся до завершения излечения.
- Подтверждения результатов остаются штатными. Существующий выбор Вожака из старого сохранения без card_heal продолжает поддерживаться.

## Практические границы проверки

Рабочая БД не использовалась для записи; справочник s1_154 не менялся. Настоящий SQL-сервер и обязательная SQL-запись battle-history Recorder в этой задаче не запускались: проверка транзакций выполнена через существующий изолированный адаптер. HTML/ожидание обоих игроков проверены настоящими PHP-рендерами, отдельный ручной браузерный прогон не заявляется.

Имеющиеся причины срабатывания on_death сохранены. Например, урон замены Вожака имеет тип impact и не начинает on_death, если старые правила этого не предусматривают; отдельный JSON-кейс проверяет отсутствие придуманной реакции. Никакие изменения правил вампиризма, регенерации, трупоедства или перераспределения ран ради новой карты не вводились.

Неустранённых ошибок по выполненным адресным и регрессионным проверкам не осталось.
